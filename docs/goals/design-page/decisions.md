## Coordinator's adjustments (2026-10-22, before the briefs started)

- **The React runtime lives in `@answerable/design/react`, not in `@answerable/ui`.** The provider needs the `Design` type and the CSS serializer; putting it beside them keeps B1 (the UI library) and B2 (the package) independent of each other, so they can run in parallel. `@answerable/ui` keeps no dependency on `@answerable/design`. The design doc's section 4 is superseded on this point.
- **The contract file exists before the briefs.** `packages/ui/src/styles/tokens.css` was generated by the coordinator from DESIGN.md with the roles below, so B1 builds on real values and B2's generator has a byte-for-byte target. B2 owns the file from now on: if the generator must differ (a value the coordinator transcribed wrongly, a rule the file needs), B2 regenerates it and says so in its report; B1 never edits it.
- **The sessions commit on their branches and do not push.** The coordinator reviews each diff, lands it on `main` and checks the Vercel deployment, as the owner's landing rule says.
- **Profile groups may carry prose keys.** `rule` and `usage` inside `elevation`, `lines` and `focus` are prose, not tokens; the emitter skips them and the page shows them.
- **Strings are copied verbatim.** Shadow, ring, easing and duration values are emitted as written in the file; only `colors` tokens are normalised to lowercase hex.
