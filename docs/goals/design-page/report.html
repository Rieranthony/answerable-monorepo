What the probes found

Every claim below was tested on this machine or against the live source today. The design rests on these.

Our DESIGN.md through the official tooling

Google ships @google/design.md 0.4.0 on npm: a parser, a linter with eleven rules, and exporters to CSS variables, Tailwind 4 and W3C tokens. Run on the file at the repository root:

As committedNothing parses. The file is wrapped in a code fence and starts with a blank line, so there is no front matter at line 1.01

Those two typos fixed28 colours, 29 type levels, 3 radii, 12 spacing steps and 42 components parse. The errors are references into our own groups ({sizes.control-md}, {elevation.xs}, {lines.interface-separator}). 43 warnings come from fontFamily, weights and rules sitting beside the type levels; the rest are references inside free text, orphaned accents, no primary, and Elevation before Layout.20142

The official model is good at what it covers: it resolves {colors.neutral-100} chains, reads rgba(0, 0, 0, 0.5) with its alpha, carries a typography reference inside a component through to the level, and hands back our six extension groups (output-rules, sizes, elevation, lines, focus, motion) as raw YAML. It also accepts "Colour" and "Shape" as section names. What it does not do is resolve a reference into a group the spec does not name, although the spec's own wording allows one.

The mechanics we rely on

Tailwind 4.3.3Inline theme values pass through

@theme inline { --color-primary: var(--primary) } emits .bg-primary { background-color: var(--primary) }. Verified for colours, font sizes, weights, radius, shadows, tracking, easing, durations and the spacing unit.

React 19.2Hoisted style blocks

A <style href precedence> rendered by a component lands in <head> on the server and the client, so the first paint carries the design.

Next 16.2Several root layouts

Route groups each own an <html>: the site stays dark, /design is light.

Google Fonts1,950 families with categories

The public metadata endpoint lists family, category, weights, axes and popularity. The CSS2 API loads any family at runtime with the weights asked for.

culori 4.0.2Any CSS colour in, hex or oklch out

Hex, rgb, hsl, hwb, lab, oklch and names parse; color-mix() does not. Black on Coral measures 8.20:1, white on Coral 2.56:1.

shadcn base-novaEvery component we need is served

badge, card, tabs, switch, checkbox, radio, select, slider, dialog, tooltip, popover, menu, table, alert, progress, skeleton, avatar, separator, textarea, toggle, kbd, toast. ID's login inputs share inputClassName.

The design in three pieces

1. A token contract in the UI library

Every visual decision a component makes reads a variable with our default, and every default can be overridden by a second variable the library never sets. Whoever declares the hook wins, with no specificity fight, and unset restores the default.

:where(:root, [data-design-scope]) {
  --primary:    var(--design-primary, #000000);
  --control-md: var(--design-control-md, 36px);
  --spacing:    var(--design-spacing-unit, 0.25rem);  /* scales every p-*, gap-*, h-*, size-* */
}
@theme inline {
  --color-primary: var(--primary);   /* Tailwind emits var(--primary) into the utility */
}

The contract covers colour roles (shadcn's twenty plus ours: overlay, on-dark, on-accent, the four-colour rotation, success, warning, info), fonts, every type level as four variables, the three weight roles, radius, the spacing unit, control and shell sizes, elevation, lines, the focus ring and motion. Each type level also becomes a utility (type-heading-h2, type-button, type-statement-xl) so a level edited in the pane moves every component that uses it. The light defaults are generated from DESIGN.md and committed, with a drift test like openapi.json; the dark scheme stays hand-written until the profile has a dark group.

The showcase needs the components the file names, so the library gains the base-nova set and restyles everything to the file: fills instead of borders, square corners, three weights, 32/36/40/48px controls, elevation instead of outlines, the black focus ring. The statement layer (hero statement, stat, quote panel, highlight panel, numbered steps, divider, accent button) is new and lives in the library too.

2. Our spec on top of design.md

The Answerable profile keeps a file valid design.md and adds typed groups the spec leaves to prose. A reference may point anywhere in the YAML tree. The official linter still reports those references as broken; our linter wraps its rules, resolves them, and the page shows both verdicts. We file the upstream issue.

GroupHoldsWhy
fontsfamily, provider (Google), weights, fallback, defaultReplaces the three keys that sit beside the type levels today; levels without a family inherit the default.
rolesrole → reference, for every contract colour, radius and fontBinds a design's own names (accent-coral, neutral-100) to the library's slots. Missing roles are inferred, which is what lets someone else's file render at all.
sizes, elevation, lines, focus, motionDimensions, shadows, width + colour pairs, the ring, durations and easingTyped instead of free text, so the pane can edit them and the emitter can write them.
spacing.unitOne dimension, requiredTailwind 4 scales from one unit; the named steps stay as documentation.
output-rulesRules for agents producing documentsKept and shown, never styled.

Our file changes in seven small ways: the fence and blank line go, the two YAML typos go, the three stray typography keys move into fonts.sans and the prose, spacing.unit: 4px and colors.primary are added, the roles group is added, and Layout moves above Elevation. The prose stays the owner's words.

3. The runtime and the page

@answerable/design is a pure package: the parser on Google's linter (server only, since that module imports node:fs), the profile resolver, a CSS emitter, a DESIGN.md writer for "Copy DESIGN.md", colour conversion, and the fonts catalogue. The UI library gains DesignProvider (the one shared state), DesignVars (the hoisted :root block) and DesignFonts (a CSS2 link for any family next/font did not self-host). /design parses the repository file at build, so the page is static, and /design.md serves the raw file.

The pane

Floating at the top right, collapsing to a 36px square, and always wearing the default design through its own scope so it stays readable whatever the page becomes. Colours: swatch, a field that accepts any CSS colour and converts it on blur, hex and oklch readouts, contrast against the role's background. Type: a combobox over the Google Fonts catalogue grouped by category, the three weight roles, the level table. Shape, spacing unit, sizes, elevation, lines, motion. Reset all, Copy CSS, Copy DESIGN.md. State lives only in the provider; the URL carries nothing yet.

Later, not in this goal

Other people's files. Paste, upload or a URL, parsed by a server action with the same parser; the roles inference and the three Google example files as fixtures make this a page change, not a library change.

Share links. The overrides encoded in the URL.

Generate with AI. A server action writes a DESIGN.md from a prompt with the Claude API, then the same pipeline; the profile's typed groups are the schema the model fills.

A dark group in the profile, so the site's hand-written dark block is generated too.
