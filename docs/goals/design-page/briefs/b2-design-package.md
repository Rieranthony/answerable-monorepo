## What done looks like

1. **The workspace.** `packages/design` (`@answerable/design`, private, `type: module`, source-only like `packages/mcp`), Prettier without semicolons, ESLint as the other packages, `bunfig.toml` with 100% line and function coverage like `packages/countries`, scripts `test`, `typecheck`, `lint`, `format`, `generate`, `fonts`. Dependencies: `@google/design.md` 0.4.0, `culori` 4.0.2 (import from `culori/fn` and build only what you use), `yaml` 2.9.1; `react` 19 as a peer and dev dependency for the runtime. No zod. Exports: `.` (client-safe: types, emitter, markdown writer, colour, fonts helpers), `./parse` (server: the parser; it imports `@google/design.md/linter`, which needs Node), `./react` (client components, `"use client"`), `./google-fonts.json`.
2. **The profile is a document.** `packages/design/PROFILE.md`: what the Answerable profile adds to design.md, group by group, with the types, the resolution rules below, and what our linter reports beyond the official one. Written for someone writing a DESIGN.md by hand; sentence-case headings, British spelling.
3. **The model.** A JSON-serialisable `Design`: `name`, `description`, `version`; `colors` (name → `{ raw, hex }`, hex lowercase, 8 digits with alpha); `typography` (level → `{ fontFamily?, size?, weight?, leading?, tracking?, transform?, numeric? }` with dimensions as strings as written); `fonts` (key → `{ family, provider: "google", weights: { body?, label?, statement?, [role]: number }, fallback, default }`); `rounded`, `spacing` (with `unit`), `sizes`, `elevation`, `lines` (name → `{ width, color }`), `focus`, `motion`, `outputRules`; `roles` (role → `{ ref?, value }`, the full contract set from decisions.md); `components` (name → property → resolved string); `sections` (`{ heading, markdown }` in document order, from the official `documentSections`); `findings` (`{ official: Finding[], profile: Finding[] }`).
4. **The parser** (`parseDesign(markdown)` in `./parse`): runs the official `lint()`, takes its model, findings and sections, then the profile pass: typed validation of the extension groups found in `unknownKeyValues` (plain type guards, with a `profile` finding per wrong shape); `rule` and `usage` keys inside `elevation`, `lines` and `focus` are prose and kept aside; references `{path.to.value}` resolved across the whole YAML tree, including into profile groups, with circular and missing references reported; `fonts` resolved and every typography level without `fontFamily` given the default font; `roles` read from the file and completed by inference: `primary` ← `colors.primary` ?? `colors.foreground`; `background` ← `colors.background` ?? `colors.surface` ?? `#ffffff`; `foreground` ← `colors.foreground` ?? `colors.on-background` ?? `colors.on-surface` ?? `#000000`; `muted` ← `colors.muted` ?? `colors.surface-container` ?? the lightest neutral ?? a 4% mix of foreground into background; `muted-foreground` ← `colors.muted-foreground` ?? `colors.on-surface-variant` ?? a 60% mix of foreground into background; `destructive` ← `colors.destructive` ?? `colors.error`; `border` ← `colors.separator` ?? `colors.outline-variant` ?? `colors.outline` ?? a 10% mix; `card` and `popover` ← `colors.surface-card` ?? `colors.surface-container-lowest` ?? background; the `-foreground` pairs from the matching `on-*` colour or the better-contrast of foreground and background; `highlight-1..4` ← the file's accent colours in order, else primary, secondary, tertiary, error; `chart-1..5` ← foreground then the highlights; `radius` ← `rounded.default` ?? `rounded.DEFAULT` ?? `rounded.md` ?? `rounded.sm` ?? `0px`; `radius-full` ← `rounded.full` ?? `9999px`; `spacing-unit` ← `spacing.unit` ?? `spacing.base` ?? `4px`; the weights from the default font's roles, else `400 / 700 / 900` clamped to what the font offers. Every inferred role carries a `profile` info finding saying what it inferred from. The official findings keep their severities; references the profile resolved are moved from the official errors to profile infos, so a valid profile file has zero errors.
5. **The emitter.** `designToTokens(design)` → the ordered list of `{ name, hook, value }` in the contract order; `serializeTokensCss(design)` → the whole `tokens.css` text; `serializeHooks(overrides, selector = ":root")` → the block the runtime injects. The generator (`bun run --filter @answerable/design generate`) reads `../../DESIGN.md` and writes `../ui/src/styles/tokens.css`; a test asserts the committed file equals the output byte for byte. Start from the committed file as the target: reproduce it, and if a value in it is wrong against DESIGN.md, fix the generator, regenerate, and report the difference.
6. **The writer.** `designToMarkdown(original, design)` writes the edited tokens back into the original document through `yaml`'s Document API so comments, order and prose survive; only values that changed are rewritten; colours as lowercase hex.
7. **Colour.** `parseColor(input) → { hex, alpha, oklch: { l, c, h } } | null` for anything culori reads (hex, rgb, hsl, hwb, lab, lch, oklab, oklch, names, `transparent`), `formatHex`, `formatOklch`, `contrast(a, b)` (WCAG) and `wcagLevel(ratio, large?)`. `color-mix()` returns null with a finding, never a throw.
8. **Fonts.** `scripts/fonts.ts` fetches `https://fonts.google.com/metadata/fonts` (strip the `)]}'` prefix), writes `src/google-fonts.json` as an array of `{ family, category, weights: number[], italic: boolean, axes: { tag, min, max }[] }` sorted by popularity then family, and the file is committed. `googleFontsHref(fonts: { family, weights: number[], italic?: boolean }[]) → string` builds the CSS2 URL (`family=Public+Sans:wght@400;700;900`, `display=swap`); `findFont(family)` looks the catalogue up case-insensitively; the catalogue is a separate import so the client loads it lazily.
9. **The runtime** (`./react`): `DesignProvider({ design, fonts?, children })` where `fonts` maps a family name to the CSS family a self-hosted `next/font` provides (`{ "Public Sans": publicSans.style.fontFamily }`); it holds `{ design, overrides }` in state and context and exposes `useDesign()` → `{ design, tokens (resolved, overrides applied), overrides, set(name, value), reset(name?), css, markdown }`. `DesignVars({ scope? })` renders `<style href="design-vars" precedence="design">` with the hooks block: by default `--design-font-sans` carrying the self-hosted family when `fonts` has the design's default family, plus every override; with `scope`, the selector is `[data-design-scope="<scope>"]`. `DesignFonts()` renders one `<link rel="stylesheet" precedence="design-fonts" href={googleFontsHref(...)}>` per family the design or the overrides name that `fonts` does not cover, with the weights the design uses. Test the markup with `react-dom/server` and the state with `happy-dom` (Bun's documented DOM for tests); the coverage gate covers the runtime too.
10. **DESIGN.md** gets the seven edits of decision D1, and nothing else: the fence and the blank line go; the two compact mappings get their space; `typography.fontFamily`, `weights` and `rules` leave the typography group for `fonts.sans` (`family: "Public Sans"`, `provider: google`, `weights: { body: 400, label: 700, statement: 900 }`, `fallback: "system-ui, sans-serif"`, `default: true`) and the four rules become a short list under the Typography heading's prose if not already there; `spacing.unit: 4px` is added and `"0.5"` becomes `half`; `colors.primary: "{colors.foreground}"` is added under Core; the `roles` group is added after `components` with the references from decisions.md; the Layout section moves above Elevation. After the edits the official CLI (`bunx @google/design.md lint DESIGN.md` or the package's `lint()`) reports only the profile references as errors and `parseDesign` reports zero errors.
11. **Tests and fixtures.** `src/fixtures/`: the repository `DESIGN.md` is read live, and the three Google examples (`examples/atmospheric-glass`, `paws-and-paths`, `totality-festival` from the design.md repository, Apache 2.0: keep their header and a `LICENSE` note) prove that a file without any profile group parses, gets every role inferred, and emits a complete tokens block. A test runs `parseDesign` on the repository file and fails on any error, so CI guards it. Everything at 100% line and function coverage; `bun run mcp:test` is not the gate for this package, `bun run --filter @answerable/design test` is, plus `typecheck` and `lint`.
