## What B1 and B2 reported, so you do not rediscover it

- **`DesignVars` renders a plain `<style data-design-vars>` in place, not a hoisted one.** B2 found that React 19.2.4 never updates a hoisted `<style href precedence>`'s text once rendered, so overrides would be lost; the plain element still comes from the server. Render `DesignVars` early in the layout, before the page content. `DesignFonts` keeps hoisted `<link precedence>` elements.
- **The provider's API** (`@answerable/design/react`): `DesignProvider({ design, fonts, children })`; `useDesign()` returns `{ design, current, tokens, overrides, set, reset, hooks, css, markdown }`; `set(name, value)` takes a contract token name (`primary`, `type-button-size`) or a design path (`colors.neutral-100`, `fonts.sans.family`), and edits through a path flow to every token that references it; `reset(name?)`. `hooks` declares every contract token (B2 changed this on the coordinator's request). Components cannot be edited with `set()`.
- **`findFont(family, catalogue)`** takes the catalogue as an argument so the client imports `@answerable/design/google-fonts.json` lazily; `googleFontsHref` and `fontStack` are in `@answerable/design`. `DesignFonts` does not clamp weights to what a picked family offers: clamp with the catalogue entry's `weights` before `set("fonts.sans.weights.<role>", …)`.
- **The model** has `refs` (path → path it references), `notes` (the `rule` and `usage` prose of elevation, lines, focus), `source` (the original Markdown), `sections` (`{ heading, markdown }`), `findings.official` and `findings.profile`, and an `inferred` flag on roles and fonts. `parseDesign` reports the repository file with zero errors; the official CLI still reports 20 `broken-ref` errors into the profile groups, which the page shows as the official verdict.
- **The components** (`@answerable/ui/components/*`): `Button` has variants `default | secondary | ghost | link | destructive | accent`, sizes `sm | default | lg | xl | icon | icon-sm | icon-lg`, and `highlight` 1 to 4 for `accent` (48px unless sized); `Badge` takes `highlight`; `Card` takes `variant="muted"`; `Field` has `FieldLabel` (with the square error marker), `FieldDescription` and `FieldError`; `TableHead` and `TableCell` take `numeric`; the statement layer is under `components/statement/`. There is no `outline` button variant and no `xs` size. `cn` knows the three weights and the `type-*` levels.
- **Tailwind in a worktree.** The worktree sits inside the main checkout, so Next infers the main checkout as the workspace root (a lockfile warning) and Tailwind's automatic source detection does not scan files that exist only in the worktree; B1 needed a temporary `@source`. Fix it properly in `apps/web/next.config.mjs` with `turbopack.root` set to the repository root (the Next docs under `node_modules/next/dist/docs/01-app/03-api-reference/05-config/` describe it), which holds for the main checkout too.
- **`tokens.css` is Prettier-ignored** in `packages/ui`; never hand-edit it. `--shadow-none` does not exist in Tailwind 4.3.3 (`shadow-none` is static), so `elevation-none` is shown as a value, not used through a utility.
