# Task plan: the Answerable admin MCP

Order, not time. Every brief starts with its failing tests, leaves its docs page complete, ends with the cleanup pass, and is reviewed against [`design.md`](design.md), `docs/08`, `docs/09` and this plan. Facts: [`findings.md`](findings.md). Choices: [`decisions.md`](decisions.md).

## Goal

A standalone, staff-only MCP, `mcps/admin` on the MCP kit, through which Answerable staff with the `owner`, `admin` or `team` role onboard and manage organisations in Answerable ID and enable the Toolbox for them; roles read live from ID; every write a controlled-class prepared intent, idempotent at ID by intent id, recorded as evidence; proven by acceptance journeys against real ID and by a hand demo with Claude Code.

## B2. The writes (Opus 5.5)

**Scope.** `packages/auth`: `UserPrincipal.upstreamAuthTime: number | null` from `upstream_auth_time` (user tokens only; CHANGELOG 0.5.0; `reference.mdx` regenerated). `mcps/admin`: the fourteen mutations of the tools table as `defineMutation` with `risk: "normal"`, targets bound to ETags, `Idempotency-Key: <intent id>` (or `.<step>`) and `x-request-id: <execution id>` on every ID call, `If-Match`/`If-None-Match` where ID takes them, receipts carrying ID's `Operation-Id`; `src/toolbox.ts` for `toolbox.enable` through the Toolbox's admin API with a `toolbox:admin` token (A1, A2: prove in a unit test against the fake ID's token endpoint extended for a second audience, and note the fallback of a second machine client); `src/fresh.ts`: the critical tools' freshness check in `prepare` (`ADMIN_REAUTHENTICATION_REQUIRED`, retry `after_state_change`); the custom codes declared per definition (`ADMIN_REAUTHENTICATION_REQUIRED`, `ADMIN_SSO_NOT_PLATFORM` if `sso.set` needs its own code, else `INVALID_INPUT`); `policyClass` fixed to `controlled`; the fake ID extended with the write routes and their replay (`Idempotency-Replayed`, 409 `idempotency_key_reused`, 412 `revision_mismatch`) so the SDK's `INTENT_STALE` path is covered by `moveTarget`.
**Tests first.** Conformance for every mutation (`examples` per tool, `moveTarget` bumps the fake row's revision); unit tests: prepare previews (summary, changes, effects, warnings) for each tool; `organisations.create` refuses a taken slug; `access.grant` refuses a scope outside `allowedScopes` and an identical active row; `sso.set` accepts a Microsoft and a Google issuer with platform credentials and refuses a generic issuer naming the workaround; commit sends `Idempotency-Key` = intent id and `x-request-id` = execution id (fake ID records them) and `If-Match` = the bound ETag; a replayed commit returns the receipt without a second ID write; a moved target answers `INTENT_STALE` with `details.targets`; an admin cannot prepare or commit an owner tool (unknown tool, denial evidence); an owner with `upstream_auth_time` older than the window answers `ADMIN_REAUTHENTICATION_REQUIRED` at prepare and at the commit of an intent prepared when fresh (the test issuer sets the claim); `toolbox.enable` posts the enable body and returns `created`/`existing`; `ADMIN_TOOLBOX_ADMIN_RESOURCE` unset answers `PRECONDITION_FAILED`; `staff.grant` finds the role group by its entitlement, not its slug. 100%.
**Docs.** `admin/index.mdx` complete: the mutation flow (prepare → `admin_commit_confirmed`), the critical operations and the freshness rule, the Errors table with every standard and custom code a person can hit (`<ErrorCodes>` plus the custom rows), Limits (no secrets, platform credentials only, creates/disable/enable without preconditions at ID, the Toolbox enable is not atomic). `mcp/errors.mdx` if a custom code deserves a cross-link.
**Must not touch.** `apps/id`; `packages/mcp` (stop and report a real gap); the Toolbox's routes.
**Gates.** `bun run mcp:check @answerable/mcp-admin`, `bun run mcp:check @answerable/auth`, `bun run mcp:test`, typecheck, lint, build, web test.
**Prompt skeleton.** "Add the writes to the Answerable admin MCP. ## The demo script

**Automated (the proof).** `bun run mcp:test:e2e` runs A1–A6: staff roles without re-authorisation, onboarding through the MCP, the new organisation's person in the Toolbox before and after the grant, refusals, idempotency, evidence.

**By hand, the lane (the whole story, local directories).** `bun packages/acceptance/scripts/admin-lane.ts`; it prints the staff email (`staff@answerable.example.test`, any company sign-in accepted), the spare organisation's details and the Claude Code commands:

1. `claude mcp add --transport http answerable-admin http://127.0.0.1:47606/mcp --client-id claude-code-admin --callback-port 47700`; `/mcp` → Authenticate → sign in as the staff email. Ask Claude for `admin_whoami`: owner, the 24 tools.
2. "Onboard Newco: create the organisation `newco`, add the domain `newco.example.test`, enable the Toolbox for `claude-code-toolbox` with `e2e`, and grant everyone `e2e/records`." Claude prepares each step, shows the previews, asks before each `admin_commit_confirmed` (A5 of the findings says whether Claude Code prompts), commits. The SSO provider for the spare directory is set by the lane itself when the organisation appears (it polls ID), because it needs the directory's secret; the lane says so.
3. `claude mcp add --transport http answerable-toolbox http://127.0.0.1:47604/mcp --client-id claude-code-toolbox --callback-port 47701`; sign in as `tester@newco.example.test` (before step 2 this stops at "Access is unavailable for this organisation"); `toolbox_whoami` lists `e2e/records`; create and delete a record.
4. Remove the staff member from `answerable-owner` through the lane's prompt (or `staff.revoke` from a second owner): the next `tools/list` shows reads only; a write is unknown.

**By hand, the owner's ID (real Entra).** Follow `/docs/admin/setup`: register the resource, the Claude Code client, the machine client (two audiences), the groups and entitlements with root; add the owner's member to `answerable-owner`; start the Toolbox (`bun run toolbox:dev`, after its own registration) and the admin MCP (`bun run admin:dev`); `claude mcp add --transport http answerable-admin http://localhost:47520/mcp --client-id claude-code-admin --callback-port 47700`; sign in with the Entra account; `admin_whoami`; create an organisation, add its domain, `sso.set` with its Entra tenant issuer and platform credentials, `toolbox.enable`, `access.grant`. Step 3 needs a person in that directory (D12).
