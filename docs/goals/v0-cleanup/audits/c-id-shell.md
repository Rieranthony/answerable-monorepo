**Estimated lines, in scope (production source, scripts, test support, configs):** about −550 / +160 if every proposal is taken (the bootstrap split C4 counted instead of its narrower fixes C2/C3). Test files would change by about −30 (forced) and −85 more if the runtime-login helper (H3) is adopted in the seven integration tests that copy it.

**The five changes that matter most:**

1. **C1 — the shutdown closes the pool under in-flight requests.** `runtime.ts:87` calls `server.stop(false)` without `await`; Bun's `stop` returns a promise that settles when in-flight requests finish, so `database.close()` ends the pool while they still run. Every SIGTERM in a rolling deploy can fail live requests. The typed lint finds exactly this line (and two misused promises in `server.ts`) and nothing else in ID.
2. **C2/C4 — bootstrap re-creates a removed platform capability, and repairs operator data inconsistently.** A capability removed through the admin API comes back at the next restart with all six admin scopes; disabling it survives. Org name, admin-resource definition and the platform-admins entitlement are reverted at every boot; the group and the capability are not; the entitlement lookup can pick a tombstone. With the binding's restrict and live foreign keys, half of the function's branches are unreachable. Split it into "provision" (no binding) and "verify" (binding), with one ownership rule.
3. **C17/C18 — test support carries 37 dead exports and five copies of the root authority.** 35 bound query wrappers that the test audit's deletions orphaned, two dead re-exports, plus duplicated context helpers with needless dynamic imports: about −160 lines of test support.
4. **C6–C9 — env.ts: longhand numeric schemas, bounds that cannot fail, a test-only branch, and `BETTER_AUTH_URL` normalised in three places at use time.** A trailing slash in `BETTER_AUTH_URL` gives the JWT issuer `http://host/` while the pages and admin audience use `http://host` (probed). Normalise once at parse, delete `lib/service-url.ts`, collapse eight numeric fields into two helpers: about −60 lines.
5. **C10/C15/C16 — scripts.** `configure-runtime-role.ts` repeats what `db:migrate` already does; the production `migrate.ts` imports test support for a `--test` mode; the schema reset is written three times; "configure a runtime role and log in as it" is written ten times. One reset helper, one test-database script, one runtime-login helper.

## 5. Challenged and kept

- **`bindQuery` (test support).** Production query functions take a branded context that only `authorize*`/`with*` can mint (WeakSet), so "call them in a transaction" is not possible without minting one; `bindQuery(inPlatformWrite)(queries.x)` mints a root context per call. After C17 about 34 wrappers remain behind roughly 80 call sites (`createOrganization` alone has 14 importing files); inlining would add a line per site. Keep `bindQuery`; simplify `bindTenantQuery` (C19).
- **`AppTesting.ssoTest` seam in `createApp`** (`app.ts:37-41,56`). Production code carrying a test seam, but the test audit moved the SSO probe's bypass here on purpose; one optional field.
- **`startRuntime` options `allowTestEnvironment`, `seed`, `databaseFactory`, `authFactory`.** Each is used by `runtime.test.ts` (lines 54, 94-96, 138-142, 156-159, 195-196, 213, 223-225) to prove pool closing on seed, auth and listen failures.
- **`createId()` wrapping `Bun.randomUUIDv7()`.** 24 production call sites; one place to change the identifier format.
- **`boundedUserAgent`.** 7 call sites across audit paths; rejects rather than truncates, as documented.
- **Client-supplied `x-request-id`** (`app.ts:47-51`). Bounded by `^[A-Za-z0-9._:-]{1,128}$`, used only for correlation (audit `requestId`, problem bodies); no decision reads it (the "markers" in `native-client-authentication.ts` are adapter inputs, not request ids).
- **Redirect targets in the pages.** 7 redirects: 2 relative (`/authorize?…`, `/login?…`), 5 to `result.data.url` returned by in-process allowlisted Better Auth routes, which validate callback and redirect URIs. Callback URLs are always built from `BETTER_AUTH_URL`, never the Host header. No open redirect.
- **Escaping.** Zero `dangerouslySetInnerHTML`/`raw(` in pages; CSP `default-src 'none'`, no script, `frame-ancestors 'none'`, `X-Frame-Options: DENY`; `same-origin` referrer and no COOP are justified in comments and tested.
- **Error copy.** All 24 codes in `error-copy.ts` have an emitter, in ID source or in Better Auth's dist (`SSO_PROVIDER_CHANGED`, `state_not_found`, `state_mismatch`, `token_not_verified`).
- **Root secret path.** `min(32)`, break-glass requires the secret (`env.ts:155-160`), comparison through `secretMatches` (`principal.ts:217-218`), boot logs only the seeded row summary and two booleans for platform applications (`runtime.ts:46-55`), env errors never echo values (tested at `env.test.ts:55-62`, 243-247, 376-388).
- **`reset-test-schema.ts` guard.** Refuses any database whose name is not exactly `answerable_id_test` (`test-database.ts:11-22`); every destructive script and the crash worker call it. A name check is enough: production is `answerable_id`.
- **`mcp-e2e-fixture.ts`.** Used: `packages/acceptance/src/id.ts:77` spawns it and CI runs it through `mcp:test:e2e`. The `--isolated-mcp-fixture` flag is a two-line guard against running it by hand. The `auth_time` getter (`:156-159`) is needed because sign-ins happen minutes after boot and the issuer copies claims at token time; the alternative (issuer defaults `auth_time`) would break the tests of unknown upstream time. Turning Better Auth's origin checks back on through `auth.$context` is the test audit's decision.
- **`operations-preflight.ts` swallowing every error into `custody_preflight_failed`.** Documented operator step (docs/06 step 5, OPERATIONS.md:50,60) whose contract is to print no key material; `checkKeyCustody` already rethrows a generic error.

- **`test-migrations.ts` and `migrations.integration.test.ts` both comparing catalogues; `regenerate-migrations.ts`.** Schema audit D1 and the test audit's "considered and left as it is".

- **`metrics.ts` `PoolObservation` optional fields, `protocol-sweep.ts`.** Small and correct; the sweep's lock, batch and stop semantics match the schema audit's D6.

## 6. Questions for the coordinator

- **Q1. Bootstrap ownership rule (C2–C5).** Recommendation: after first provision, boot owns only what code defines and verifies the binding. Concretely: org name, group, entitlement and capability are written once (first boot) and belong to operators afterwards; the admin resource's definition stays code-owned (boot syncs it so a release that adds an admin scope reaches the resource) and `updateResource` refuses the bound resource like disable and delete already do (area B, `services/resources.ts`); audit only when something changed. Fix C2 regardless of the rest.
- **Q2. Delete `/api/admin/docs` and `@scalar/hono-api-reference` (C11)?** Recommendation: yes; /docs already renders the reference from the same document.
- **Q3. `/error` details (C23).** Recommendation: render only code-shaped `error_description` values. Owner call if IT staff rely on upstream free text.
- **Q4. Variables nobody sets (3a).** 15 of 29 service variables are never set to a non-default value. Most are documented operational knobs (docs/06:89); keep them. Recommendation: delete `PLATFORM_ORGANIZATION_SLUG` and `PLATFORM_ORGANIZATION_NAME` (constants in bootstrap; the first is ignored after first boot, the second fights admin-API renames, and both are used once under Q1); keep `ADMIN_RESOURCE_IDENTIFIER` (consumers' docs name it).
- **Q5. CORS on `/api/admin/*` and `/auth/*` (`app.ts:82-100`).** Credentialed CORS is granted to `BETTER_AUTH_TRUSTED_ORIGINS`, which must also list every identity-provider endpoint origin, tenant-run issuers included, and the admin principal's Origin check (`principal.ts:340-350`) uses the same list. Better Auth's default `SameSite=Lax` keeps the session cookie off cross-site fetches, so this is defence in depth, and no browser client of `/api/admin/*` exists today. Recommendation: drop the `/api/admin/*` CORS middleware until a console exists, or split the variable into IdP origins and browser origins. Owner decision; not counted as a finding.
- **Q6. Typed lint in `apps/id`.** `no-floating-promises` + `no-misused-promises` find exactly the C1 and C31 lines today; lint time for non-test files goes from 4.1 s (current config, all files) to 10.9 s. Recommendation: enable for `src` and `scripts`; it is automation (lowest preference) but it guards the class of bug C1 is.
- **Q7. `hono-tailwind` at runtime (C30).** Recommendation: only if a spike shows the bundle runs without `node_modules`; otherwise keep.
- **Q8. Fixture provisioning (C35).** Coordinate with area E: moving tenant provisioning into `startId` touches `packages/acceptance`.
- **Q9. `drizzle.config.ts` `dbCredentials` (C13).** Trivially dead, but it is migration tooling the schema audit owned; confirm it may go.
- **Q10. Cross-area: errors logged without identity.** `problem.ts:166-172`, `protocol-sweep.ts:78-82` and the pages (C24) log an event and a request id but never the error's class or Postgres code, so production failures cannot be told apart. Recommendation for area B: log `error.name` and, for database errors, the SQLSTATE and constraint name (never the message).
- **Q11. Optional: drop `export-openapi.ts`.** `openapi.integration.test.ts` already builds both documents on `testEnvironment()`; an `UPDATE_OPENAPI=1` write in that test (the pattern `UPDATE_MANIFEST=1` already uses) would replace the script and the `--env-file` requirement. Recommendation: take C14 now, this only if the owner likes the manifest pattern.
