## Goal

Three AWS accounts in an Organization, London-only by policy, with an organisation trail and GuardDuty, people signing in through IAM Identity Center, and in each workload account a Terraform state bucket and the GitHub OIDC roles the pipeline will assume. No IAM user with long-lived keys remains in use once B7 is done.

## What to build

### `infra/aws/org` (management account)

- `aws_organizations_organization` with all features and the `SERVICE_CONTROL_POLICY` type enabled; an OU `workloads`; `aws_organizations_account` ×2 (`answerable-staging`, `answerable-production`) in it, with `close_on_deletion = false` and `lifecycle { prevent_destroy = true }`.
- SCPs attached to `workloads`: deny every action outside `eu-west-2` except the global services that only answer in `us-east-1` (IAM, STS, Organizations, Budgets, Pricing, Support, Health, CloudFront's and Route 53's APIs are not needed and stay denied); deny `organizations:LeaveOrganization`; deny stopping or deleting CloudTrail and GuardDuty; deny every action by the member accounts' root user (`aws:PrincipalArn` ending in `:root`).
- Organisation CloudTrail: all regions, management events, log file validation, to an S3 bucket in the management account with Object Lock (governance, 365 days), SSE-KMS, public access blocked, lifecycle to Glacier after 90 days.
- IAM Identity Center: an instance in `eu-west-2`, permission sets `AdministratorAccess` and `ReadOnlyAccess`, the owner's user assigned to both member accounts and the management account. (Identity Center's instance is created in the console once; Terraform manages the permission sets and assignments.)
- AWS Budgets per member account: $150 staging, $300 production, alerts at 80% and 100% of forecast and actual to the alarm email.
- State: the management account's own bucket, created by the `bootstrap` root below with `account = management`.

### `infra/aws/bootstrap` (run once per account)

Variables: `account` (`management` | `staging` | `production`), `github_repository` (`Rieranthony/answerable-monorepo`). Resources:

- S3 state bucket `answerable-tfstate-<account>-<id>`: versioning, SSE-KMS with a key created here, public access blocked, bucket policy that denies non-TLS and requires the KMS key; Terraform ≥ 1.10's `use_lockfile = true` so no DynamoDB table.
- `aws_iam_openid_connect_provider` for `token.actions.githubusercontent.com`.
- Roles with `sts:AssumeRoleWithWebIdentity` trust on that provider, `aud = sts.amazonaws.com` and `sub` pinned:
  - `github-plan`: `sub` matches `repo:<repository>:pull_request` and `repo:<repository>:ref:refs/heads/main`; `ReadOnlyAccess` plus read of the state bucket and `s3:PutObject` on the lockfile only.
  - `github-apply`: `sub` is `repo:<repository>:environment:aws-<account>`; the permissions Terraform needs in that account (an allowlist of the services the modules use, scoped to the region, not `AdministratorAccess`; the brief lists each service as the modules land in B4 and tightens then).
  - `github-deploy`: same `sub`; ECR push on the three repositories, `ecs:RunTask`, `ecs:UpdateService`, `ecs:Describe*`, `ecs:RegisterTaskDefinition`, `iam:PassRole` on the task and execution roles, `ssm:PutParameter` on `/answerable/<account>/images/*`, `logs:GetLogEvents` on the task log groups (to print a failed migration's output).
  - `github-ecr-push` (production only): `sub` is `repo:<repository>:ref:refs/heads/main`; ECR push on the three repositories and nothing else, so a `main` push can stage the image in production without touching its services ([D9](../decisions.md)).
- Outputs: the bucket name, the role ARNs, the provider ARN. The owner copies the ARNs and account IDs into GitHub environment variables `AWS_ACCOUNT_ID`, `AWS_PLAN_ROLE_ARN`, `AWS_APPLY_ROLE_ARN`, `AWS_DEPLOY_ROLE_ARN` on `aws-staging` and `aws-production`, and `AWS_PRODUCTION_ECR_PUSH_ROLE_ARN` as a repository variable.

Apply order: `bootstrap` for `management` with local state, then `terraform init -migrate-state` into its bucket; `org` (creates the member accounts); then `bootstrap` for each member account through Identity Center credentials (`aws sso login`), migrating its state the same way. The runbook (`infra/aws/README.md`, B6) records the exact commands; this brief writes them first in `infra/aws/README.md` under "Account foundation" so B6 only completes the file.

## Constraints

- Providers pinned exactly (`hashicorp/aws` 6.68.0 or the current version, [findings](../findings.md#versions-to-pin-checked-8-october-2026)); `required_version` pins the Terraform minor (1.16).
- No third-party modules ([D3](../decisions.md)).
- Nothing is created in `us-east-1` except what AWS forces there (the OIDC provider and IAM are global).
- The management account hosts no workload and no state but its own and the trail's.
