| Admin MCP (`mcps/admin`) | `bun src/server.ts` from source | `ADMIN_PORT`, default 47520 | `/health` from the SDK (`packages/mcp/src/server.ts`) | Postgres `answerable_admin` through `Bun.SQL`: only `@answerable/mcp-postgres`'s intents and evidence | ID's admin API on every request (roles are never cached, `docs/11`); the Toolbox's admin API; exits 1 at start when ID does not answer `readPlatform` |
| Web (`apps/web`) | Vercel | — | — | — | Stays on Vercel; it never calls ID at runtime (`docs/06`) |

- The Toolbox mounts the e2e provider and imports `mcps/e2e/dist/records.html` at module load: its image must run `bun run --filter @answerable/mcp-e2e build`.
- The SDK checks the `Host` header against the resource URL's hostname (`packages/mcp/src/server.ts`): the ingress must pass the public `Host` through unchanged.
- ID requires in production: `NODE_ENV=production`, `BETTER_AUTH_URL` (`https://`, the issuer), non-empty origin-only `BETTER_AUTH_TRUSTED_ORIGINS`, `TRUSTED_PROXY_CIDRS`, `BETTER_AUTH_SECRET`, `DATABASE_URL` as a restricted runtime login; it refuses `NODE_ENV=test` and a privileged database role before listening (`apps/id/src/env.ts`, `src/runtime.ts`, `docs/06`).
- ID's client address comes from `x-forwarded-for`, walked from the right skipping `TRUSTED_PROXY_CIDRS` (`apps/id/src/auth.ts`); a production `/auth/*` or `/api/admin/*` request with no resolvable address gets `403 untrusted_ingress`. The resolver cannot see the socket peer, so the network must admit only the ingress (`apps/id/README.md`).
- ID's migrations need the schema owner (`DATABASE_MIGRATION_URL`) and provision `DATABASE_RUNTIME_ROLE` on every run; the migration connection waits 5 s for a lock and 5 minutes per statement, and refuses a changed or missing applied file (`apps/id/scripts/migrate.ts`).
- The MCP migrator applies directories in order, each file in its own transaction under advisory lock 4751300, records `<directory>/<file>` with a SHA-256 and refuses a changed applied file (`packages/mcp-postgres/src/migrate.ts`). Since B1 (13 October 2026) the Toolbox and the admin MCP migrate as owners and serve as restricted runtime logins, and refuse to start as the owner.
- Secrets: four independent families for ID (`BETTER_AUTH_SECRET`/`BETTER_AUTH_SECRETS`, `UPSTREAM_TOKEN_SECRETS`, `ROOT_ADMIN_SECRET`, the platform application secrets), none allowed in Postgres or its backups; a restored database is unreadable without the keys active when its rows were written (`docs/06` § Operating it). The MCPs add `TOOLBOX_ID_CLIENT_SECRET` and `ADMIN_ID_CLIENT_SECRET`.
- Postgres sizing rule: `max_connections` ≥ replicas × `DATABASE_POOL_MAX` (20) + migration and operator sessions (`docs/06`). `Bun.SQL`'s default pool is 10 per process.
- A machine client's secret is generated by ID: `POST /api/admin/v1/clients` with `tokenEndpointAuthMethod: client_secret_basic` returns `clientSecret` once; a retry of the same idempotency key returns the receipt without it, and a lost secret needs `POST /clients/:clientId/rotate-secret` (`apps/id/src/services/clients.ts`). `register` stores the secret from the creation response and rotates when it is missing.
- `admin_operations` and `audit_events` are kept forever and nothing prunes them (`docs/06` § Storage growth); `Q-EVIDENCE-RETENTION` measures the MCPs' growth.
- The release gate `reports/answerable-id-release-decision-plan.md` is no-go until E1–E8 close; the deployment-shaped rows are E5 (secret store, key delivery), E6 (topology, ingress, budgets) and E7 (backup and restore, RTO/RPO).

## Database TLS from the services

- `pg` 8.16.3 (ID) parses `sslmode` and `sslrootcert` from the URL: `sslrootcert=<file>` is read into `ssl.ca` and `sslmode=verify-full` keeps `rejectUnauthorized` true.
- `Bun.SQL` 1.3.1 honours `sslmode` in the URL but ignores `sslrootcert` (and Postgres rejects the parameter), so `@answerable/mcp-postgres` gained `connect(url)`, which reads the file and passes `tls: { ca }` (B2, 13 October 2026).
- Civo documents nothing about TLS for its managed PostgreSQL: its connect page shows a plain connection string, and its provider exposes no certificate attribute (19 October 2026, [`simplify/findings.md`](simplify/findings.md)). The bootstrap Job records whatever certificate the database presents on first use and logs its fingerprint; whether Civo serves TLS at all is a first-run question.

## Cloudflare in front

Checked on 8 October 2026 against Cloudflare's developer documentation and API; the Origin CA facts on 19 October.

- **Two zones, both on Cloudflare** (10 October 2026): `answerable.org` (`crystal`/`cullen.ns.cloudflare.com`, shared with Vercel's DNS-only `www`) and `answerable-staging.uk` (`simon`/`mina.ns.cloudflare.com`, registered by the owner for staging).
- **Universal SSL covers only the apex and first-level names** ([limitations](https://developers.cloudflare.com/ssl/edge-certificates/universal-ssl/limitations/)). Every hostname in [D12](decisions.md) is first-level, so Universal SSL suffices.
- **`X-Forwarded-For`**: Cloudflare keeps an incoming header and appends the address that connected to it ([HTTP headers](https://developers.cloudflare.com/fundamentals/reference/http-headers/)); Traefik appends the load balancer's private address. ID's right-to-left walk over Cloudflare's ranges, the private network and the pod range stops at the client.
- **Cloudflare's ranges**: 15 IPv4 and 7 IPv6 CIDRs from `https://api.cloudflare.com/client/v4/ips`. Terraform reads them at apply time for the load balancer's firewall, Traefik's trusted peers and ID's `trusted-proxies` ConfigMap, so a change in the list needs an apply.
- **Authenticated Origin Pulls** is on every plan. Zone-level uses "a certificate that you upload" and "provides stricter security because the certificate is exclusive to your account" ([AOP](https://developers.cloudflare.com/ssl/origin-configuration/authenticated-origin-pull/)). Terraform makes and uploads it (D19).
- **Origin CA**: create, list, get and revoke authenticate with "an API token with Permissions that include Zone-SSL and Certificates-Edit"; the certificates are "compatible with Strict SSL mode", can hold wildcards and up to 200 names, last up to 15 years, and "only encrypt traffic between Cloudflare and your origin server"; "Cloudflare does not currently send expiration notifications" ([Origin CA](https://developers.cloudflare.com/ssl/origin-configuration/origin-ca/)). Terraform's `cloudflare_origin_ca_certificate` (provider 5.x) takes a CSR, the hostnames, `origin-ecc` and a validity of 7 to 5475 days.
- **Streaming**: Cloudflare's Proxy Read Timeout is 125 s by default; the SDK's streams send a keep-alive more often than every 10 s, so MCP streams survive the proxy. Cloudflare preserves the `Host` header to the origin on non-Enterprise plans.
- **Bot and browser heuristics break machines**: Bot Fight Mode and Browser Integrity Check challenge non-browser clients with an HTML page; they must be off for these hostnames ([D18](decisions.md)).
- `www.answerable.org` is DNS-only, so zone-wide SSL settings do not change how the site is served.

## Civo

Read from Civo's pages on 10 and 19 October 2026.

- The control plane is free; a Medium node (2 vCPU, 4 GB) is $21.73 a month; a load balancer $10.86; a Small PostgreSQL 17 database $43.45, a Medium $86.91; an object store is sold in 500 GB blocks at $5.43.
- Civo's managed PostgreSQL is in beta and offers only version 17; backups are "automatic" and otherwise undocumented; "you can choose to run additional nodes", "always choose an odd number of nodes", and a multi-node database "can continue to operate even if one or more nodes fail", with no mechanism documented ([getting started](https://www.civo.com/docs/database/getting-started)). "The default database name will be `postgres`" ([connect](https://www.civo.com/docs/database/postgresql/connect)).
- Civo's nodes are amd64: "Civo's nodes are `amd64`, so the image has to be built for `linux/amd64`"; an arm64 image "fails to start with an exec-format error" ([Civo Learn](https://www.civo.com/learn/deploy-llama3-kubeflow-kubernetes-cpu-serverless)).
- A Kubernetes `Service` of type `LoadBalancer` creates a Civo load balancer that a Civo firewall can restrict; Civo clusters always have a public API address; Civo API keys are per account and unscoped; Civo offers no managed secrets service.
- The Terraform provider `civo/civo` 1.3.3 names the resources `civo_vpc_network`, `civo_vpc_firewall`, `civo_vpc_reserved_ip`, `civo_kubernetes_cluster`, `civo_database`, `civo_object_store` and `civo_object_store_credential`; `civo_database` exposes `dns_endpoint`, `endpoint`, `private_ipv4`, `port`, `username`, `password` and `status`, and keeps the administrator's password in state; the cluster's kubeconfig is in state with `write_kubeconfig = true`.
- The Civo CLI 1.5.5 reads `CIVO_TOKEN` and `CIVO_REGION` from the environment; `civo objectstore create NAME --size 500 --owner-name CREDENTIAL --wait`, `civo objectstore credential create NAME --wait`, `civo objectstore credential ls -o json` (keys `name`, `access_key`, `status`) and `civo objectstore credential secret --access-key KEY -o json` are what the bootstrap workflow uses.

## GitHub

- `Rieranthony/answerable-monorepo` is public; environments `Preview` and `Production` exist (Vercel's). Environment secrets are encrypted with a libsodium sealed box before they reach GitHub, are write-only and masked in logs; an environment can be restricted to branches and tags and require reviewers.
- The hosted runners `ubuntu-24.04` ship Docker, OpenSSL 3 and `gh`.
- Actions are pinned by commit SHA and binaries by version and SHA-256 in `.github/actions/setup-tools/action.yml`.

## Open facts the first run must measure

- Whether Civo's database serves TLS, which certificate it presents, and whether it names the private address the services use.
- Whether Civo's object store honours Terraform's `use_lockfile` (S3 conditional writes); the fallback is `use_lockfile = false` and one run at a time, which the workflows' concurrency groups already enforce.
- The load balancer's path through the node-port firewall and its private-network-only egress; the address Traefik sees without PROXY protocol; whether Cilium tunnels over VXLAN.
- `max_connections` of the Small database; the restore's RTO and RPO; the first month's bill.
