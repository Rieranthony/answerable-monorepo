# Task plan: deploying Answerable on Civo

Order, not time. The log is [`progress.md`](progress.md); the decisions as they were taken are in [`decisions.md`](decisions.md); the facts in [`findings.md`](findings.md). The 19 October simplification that reshaped the deployment has its own record in [`simplify/`](simplify/task_plan.md).

**Status: built, on `main`, reshaped on 19 October 2026 so that nothing is done by hand from a laptop. Next: B7a, the first staging run, which is five pasted secrets, one bootstrap workflow, a tag, a sign-in and one more workflow ([`briefs/b7.md`](briefs/b7.md), [`infra/README.md`](../../../infra/README.md)).** The owner's instruction (8 October 2026): deploy Answerable ID, the Toolbox and the admin MCP in the UK as code, with Postgres where needed, outstanding security, everything in containers, the web app staying on Vercel, horizontal scaling when needed, Kubernetes allowed, low cost, staging first with production one step away, documented, and tested locally where possible, cutting no corners. Added on 19 October: as much automation as possible, secrets in GitHub environments, Civo only, a tag ships each environment.

## What done looks like

1. A tag `staging/<name>` on a commit of `main` applies staging's infrastructure, builds the images, migrates and deploys **staging** at `id.answerable-staging.uk`, `toolbox.answerable-staging.uk` and `admin-mcp.answerable-staging.uk`, and a smoke test proves them through Cloudflare.
2. A tag `production/<name>` on a commit staging has shipped, approved by the owner, stands up or updates **production** at `id.answerable.org`, `toolbox.answerable.org` and `admin-mcp.answerable.org` with the exact image digests staging ran.
3. Every Civo and Cloudflare resource, every certificate and the GitHub environment's own settings are Terraform in `infra/civo`, applied from GitHub before every deploy.
4. The images, the migrations, the database bootstrap, the registration of the MCPs in ID and the first-run steps are proved locally by `bun run infra:test` on a production-shaped kind cluster, and in CI on every push.
5. The security model holds: one Civo account per environment, a private network with firewalls, Cloudflare as the only path with origin pulls verified by Traefik, restricted database roles for all three services, verified TLS to Postgres, every secret in a GitHub environment or generated where it is used, and backups proved by a restore.
6. `docs/12-deployment.md` says what runs where and why, `infra/README.md` says how to run, ship, roll back, rotate, restore and scale, and `docs/02-plan.md`'s register reflects what this goal resolved.

Out of scope: moving the web app off Vercel, a second region, closing the ID release gate (E1 to E8 in `../../../reports/answerable-id-release-decision-plan.md`), Redis, email, KMS-backed token signing, OpenBao (withdrawn, D29).

## The owner's requirements, decided

| Requirement | Decision |
| --- | --- |
| Deploy as code | Terraform, hand-written and pinned, one root under `infra/civo` with a var file per environment, plus two Helm charts ([D3](decisions.md), [D21](decisions.md)) |
| Civo only | Both environments in two Civo accounts, LON1; the record names no other cloud ([D28](decisions.md)) |
| Nothing from a laptop | Every secret in a GitHub environment or generated by a workflow, Terraform or a Job; Terraform and the deploys from GitHub Actions ([D23](decisions.md), [D33](decisions.md), [D34](decisions.md), [D38](decisions.md)) |
| Postgres where needed | One Civo Database PostgreSQL 17 per environment with three databases, separate owner and runtime logins, verified TLS ([D5](decisions.md), [D26](decisions.md), [D37](decisions.md)) |
| Outstanding security | Account per environment, private network and firewalls, Cloudflare-only admission with origin pulls verified by Traefik, Origin CA certificates, least-privilege database roles, a namespace-scoped deploy identity, pinned actions, a reviewer on production ([D18](decisions.md), [D22](decisions.md), [D25](decisions.md), [D30](decisions.md), [D35](decisions.md)) |
| UK region | Civo `LON1` only |
| Containers | Images from the monorepo, amd64, non-root, read-only, signed, deployed by digest ([D24](decisions.md), [D36](decisions.md)) |
| Web stays on Vercel | Untouched; production's records sit beside Vercel's in the `answerable.org` zone, staging has its own zone ([D12](decisions.md)) |
| Cloudflare in front | Proxied records, Full (strict), Authenticated Origin Pulls, Cloudflare's ranges as the only admitted source and as ID's trusted proxies, challenges off for the API hostnames ([D18](decisions.md), [D19](decisions.md), [D31](decisions.md)) |
| A tag ships | `staging/*` and `production/*`, production only after staging and the reviewer ([D8](decisions.md), [D32](decisions.md)) |
| Horizontal scaling when needed | HorizontalPodAutoscalers; two replicas per service at least, spread across nodes ([D21](decisions.md)) |
| Kubernetes allowed | Used ([D20](decisions.md)) |
| Low cost | About $103 a month for staging; about $170 for production ([`docs/12`](../../12-deployment.md#cost)); production costs nothing until its first tag |
| Documented and tested locally | `docs/12`, `infra/README.md`, `bun run infra:test` on the kind cluster, `bun run infra:check` on the charts, Terraform and workflows |

## Topology, per environment

```
Browsers, MCP hosts, machine clients
        │ HTTPS
        ▼
Cloudflare (proxied records, Full strict, origin pulls, no challenges on API hosts)
        │ HTTPS + origin-pull client certificate          GitHub Actions, on a tag
        ▼                                                         │ terraform apply · build → GHCR · helm upgrade
┌─ one Civo account per environment, LON1 ──────────────────────────────────▼───────┐
│  Civo load balancer: 443 from Cloudflare's ranges only (firewall)                  │
│        │                                                                           │
│  Civo Kubernetes · namespace answerable                                            │
│     Traefik: Origin CA certificate, origin-pull verify, trusted proxies            │
│        │                                                                           │
│     id (×n) · toolbox (×n) · admin-mcp (×n) · Jobs: bootstrap, migrate, register   │
│     Secrets: id-env from the GitHub environment, the rest generated in the cluster │
│        │ TLS verify-full, runtime logins, private network                          │
│  Civo Database PostgreSQL 17, backups                                              │
│  Terraform state in Civo's object store (made by the bootstrap workflow)           │
└────────────────────────────────────────────────────────────────────────────────────┘
```

The Toolbox and the admin MCP reach ID at its public issuer through Cloudflare, so that one URL is the issuer everywhere. `TRUSTED_PROXY_CIDRS` is Cloudflare's published ranges plus the private network and the cluster's pod range, written by Terraform into the ConfigMap `trusted-proxies` ([D22](decisions.md)).
