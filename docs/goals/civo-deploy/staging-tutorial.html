Part 1

GitHub

One token so that workflows can write the environment's secrets, and the environment itself.

1.1Create a fine-grained token

3 min

On GitHub: your profile picture > Settings > Developer settings > Personal access tokens > Fine-grained tokens > Generate new token.

  • Name: answerable-secrets. Expiration: one year; put the date in your calendar now.
  • Repository access: Only select repositories > answerable-monorepo.
  • Repository permissions: Environments: Read and write, Secrets: Read and write. Nothing else (Metadata: Read is added by itself).

Copy the token: it is shown once. It is one of the five values of part 5.

You should see the token listed under Fine-grained tokens with the one repository and the two permissions.

1.2Create the environment

1 min

In the repository: Settings > Environments > New environment > staging > Configure environment.

  • Leave Deployment branches and tags at No restriction. Terraform restricts it to main and staging/* on the first apply.
  • No required reviewers for staging.
You should see an empty environment named staging, beside Vercel's Preview and Production.

Part 3

Cloudflare

One token scoped to the staging zone, and one switch the token cannot flip.

3.1Create the token for the zone

4 min

Cloudflare dashboard > your profile > API Tokens > Create Token > Create Custom Token. Name it answerable-staging terraform.

ZoneZone · Read ZoneDNS · Edit ZoneSSL and Certificates · Edit ZoneZone Settings · Edit ZoneConfig Rules · Edit ZoneCache Rules · Edit

Zone Resources: Include > Specific zone > answerable-staging.uk. No client IP filtering, no TTL.

Copy the token: it is shown once. Terraform uses it for the records, the settings, the rules, the origin-pull certificate and the origin certificate (Cloudflare's Origin CA needs only SSL and Certificates Edit).

You should see the token listed with six permissions on one zone.

3.2Turn Bot Fight Mode off

1 min

Zone answerable-staging.uk > Security > Bots (or Security > Settings in the newer dashboard) > Bot Fight Mode: Off.

Why by hand. No API token can change it, and left on it would show an HTML challenge to Claude Code and to our own servers calling ID.

Part 6

Bootstrap

One workflow creates the Terraform state bucket in Civo and generates ID's secrets into the environment.

6.1Run it

3 min

Repository > Actions > Bootstrap an environment > Run workflow > environment staging, rotate none. Or from the repository folder:

gh workflow run bootstrap.yml --ref main -f environment=staging
gh run watch
You should see the run's summary: "Environment staging is bootstrapped: the state bucket answerable-staging-tfstate exists and the environment holds its credential and ID's secrets." The environment now lists STATE_ACCESS_KEY_ID, STATE_SECRET_ACCESS_KEY, BETTER_AUTH_SECRET, UPSTREAM_TOKEN_SECRETS and ROOT_ADMIN_SECRET beside your five.
If it stops at "has no secret …", a name in 5.1 is misspelt. Fix it and run again: the workflow is safe to repeat and writes only what is missing.
Part 7

The first tag

A tag on main builds the servers, the cluster, the database and the certificates, then deploys and smoke-tests. Civo starts billing here.

7.1Push the tag

1 min, then about 45 min of waiting
cd ~/code/answerable && git pull
git tag staging/first main
git push origin staging/first
gh run watch
You should see the run Deploy staging go through: the guard, CI (about 15 min), Apply the staging infrastructure (the first apply creates the cluster, the database and the certificates: 15 to 25 min), the four builds, Deploy to staging, Smoke test staging with every check PASS.
What the first apply also did. It restricted the environment to main and staging/* and wrote KUBE_SERVER, KUBE_CA and KUBE_TOKEN into it, so the deploy job that followed could sign in to the cluster. Check the environment's secret list: three more names.

7.2If the deploy could not pull an image

3 min

New GHCR packages are private, and the cluster pulls without credentials. On GitHub, your profile > Packages: open each of answerable/id, answerable/toolbox, answerable/admin-mcp and answerable/ops > Package settings > Change visibility > Public. Then rerun the failed jobs:

gh run list --workflow deploy-staging.yml --limit 1
gh run rerun <run id> --failed

Once per package; the next tags need nothing.

7.3Record three things from the run's log

3 min
  • In Deploy to staging, the ops-bootstrap Job's lines: the database certificate's SHA-256 fingerprint, and whether it covers the host. Write the fingerprint and today's date into reports/staging-evidence.md later.
  • In Apply the staging infrastructure, the output origin_certificate_expires_on: the origin certificate's expiry, fifteen years out. Calendar it anyway.
  • In Deploy to staging, the ops-register Job's last lines: the two claude mcp add commands for part 9.
If ops-bootstrap says the database serves no TLS, stop here and say so: Civo documents nothing about it, and that answer changes the plan.

8.1Sign in once

2 min

Open https://id.answerable-staging.uk/login and sign in with your work account. If Microsoft asks for admin consent for the app in your tenant, grant it.

8.2Make yourself the administrator

3 min

Repository > Actions > Ops > Run workflow > environment staging, command make-admin, email your work email. Or:

gh workflow run ops.yml --ref main -f environment=staging -f command=make-admin -f email=you@answerable.org
gh run watch
You should see in the Job's log: added to answerable-owner (the admin MCP's owner role), added to platform-admins, and "Root is locked now". The smoke test follows.
Root is locked. From now on nothing can use the root secret; it stays in the environment as the break-glass only (infra/README.md, Break glass).

Part 10

Finish

Two proofs and the evidence.

10.1Only Cloudflare gets in

2 min

The load balancer's address is Terraform's load_balancer_ip output in the apply's log. Call it directly, bypassing Cloudflare:

curl -sS --max-time 10 --resolve id.answerable-staging.uk:443:<load balancer address> https://id.answerable-staging.uk/healthz
You should see a timeout: your address is not in Cloudflare's ranges, so the firewall drops it. (From a Cloudflare address it would reach Traefik and fail the TLS handshake for lack of the client certificate.)

10.2Write the evidence

10 min

Start reports/staging-evidence.md with today's date, each job's duration from the run, the database certificate's fingerprint, the origin certificate's expiry, and the smoke test's table. Brief B7a lists what else to measure in the coming days: the address proof, the restore drill, connections and latency, the first bill.

If something goes wrong

Every workflow is safe to run again. The message names what to fix.

You seeWhat it means and what to do
Bootstrap: "the environment staging has no secret …"A name in 5.1 is missing or misspelt. Paste it, run again.
Deploy staging: "points at …, which is not on main"The tag is on another commit. Tag a commit of main.
Apply the staging infrastructure: a Cloudflare error about permissionsThe token lacks one of the six permissions of 3.1, or is scoped to the wrong zone. Fix the token, paste it again, run again.
Apply the staging infrastructure: "Error acquiring the state lock"Another run is applying. Wait for it; runs queue by themselves.
Apply the staging infrastructure: an error writing staging.tfstate.tflockCivo's object store refuses Terraform's lock file. Say so: the fallback is use_lockfile = false in infra/civo/backend.tf, one run at a time, which the workflows already enforce.
Deploy to staging: ImagePullBackOffThe packages are private. Step 7.2.
Deploy to staging: ops-bootstrap fails with a TLS messageEither the database serves no TLS (stop and report) or its certificate does not name the private address (the log says so; infra/civo/README.md, the database row of the first-apply questions).
Smoke test staging: FAIL on every checkThe edge is catching up: Cloudflare's records and Traefik's routes take a minute. The test retries for five; rerun the job if it ran out.
Smoke test staging: FAIL on the MCPs onlyops-register did not run or failed; its log is in the deploy job. The MCPs wait at zero replicas until it has written their client Secrets.
Ops make-admin: "no member of the platform organisation has the email …"Sign in once (8.1) with that exact address, then run again.
Ops make-admin: "root_locked"You are already a platform administrator. Nothing to do.
Claude Code: Authenticate failsBot Fight Mode is on (3.2), or the redirect URIs (4.1) are wrong.
