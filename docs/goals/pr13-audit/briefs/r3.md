# R3: per-MCP roles replaced with grants (D-3)

Read [`README.md`](README.md) first, then D-3 in [`../decisions.md`](../decisions.md).

**Goal.** The shared MCP database keeps one schema per MCP and row-level security by organisation, with no per-MCP Postgres roles:
- the migrator owns every MCP schema and runs its migrations;
- each serving login is granted the MCPs it serves;
- a borrow sets the search path and the organisation, nothing else.

**Model.** Opus 5.5.

**Read:**
- B2, B3, B6 and B9 (`../audits/B.md`), and B's probes in its report;
- this session's reproduction in `../findings.md` (Audit B);
- `packages/mcp-postgres` in full;
- `infra/ops/src/bootstrap.ts`;
- `scripts/mcp/database.ts` and `role-switching.ts`;
- the MCP CLI's D1, D11 and D19, and `docs/goals/mcp-cli/findings.md`'s probes.

## What to build

1. **Provisioning** (`provision.ts`):
   - the migrator login owns each MCP's schema;
   - each serving login gets `usage` on the schemas of the MCPs it serves, and nothing on the others;
   - delete the per-MCP owner and runtime roles and their memberships;
   - keep provisioning idempotent and safe to run on every deploy;
   - decide whether the role lock is still needed, and say why.
2. **Migration** (`migrate-mcp.ts`):
   - each MCP is migrated as the migrator, with drizzle's own migrator and the MCP's journal in its schema, if drizzle 0.45.4 allows that cleanly;
   - after each migration, the serving logins get DML on the MCP's tables and sequences;
   - delete the text scanner (B3), and keep `withoutSchemaCreation` while provisioning creates the schema;
   - an applied migration whose text changed is still refused.
3. **The borrow** (`mcp-database.ts`):
   - it sets the search path and `answerable.organisation_id`;
   - no role switch and no reset on release (B6);
   - a connection released inside a transaction is still destroyed.
4. **The serving login's check** (`serving-login.ts`): it checks that the login has usage on every MCP it serves, instead of membership.
5. **Row-level security** stays as it is. Prove it again:
   - a serving login, which is not a table's owner, sees only its organisation's rows;
   - with the setting reset, it sees none.
6. **The `own` mode** stays (D-2): its owner login owns the schema and its runtime login is granted, by the same grant step.
7. **Delete:**
   - the role prefixes, with their parameters in every signature;
   - the `*_MCPS_ROLE_PREFIX` variables;
   - `scripts/mcp/role-switching.ts` and `bun mcp check`'s scan step;
   - the docs' role rules.

   Tests isolate by database name and by a login of their own, which must stay unique, because logins are cluster-wide too.
8. **The bootstrap and the chart** follow: fewer statements, the same Secrets. Check `infra/ops/src/bootstrap.test.ts` against B11, but leave B11's rewrite to R4.
9. **`bun mcp`:** `new`, `db migrate`, `dev` and `check` follow the new model in the development and test databases.
10. **Docs:**
    - `database.mdx`, `docs/12-deployment.md`, `AGENTS.md` and `docs/goals/mcp-cli/decisions.md` (a note under D1);
    - `reference.mdx`, regenerated.
11. **The 200-MCP benchmark** (`packages/mcp-postgres/bench/mcp-database.ts`) runs on the new model:
    - report provisioning, the first and the empty migration, a burst of 1,000 queries and one query through `mcpDatabase`;
    - compare them with M9's numbers in `reports/mcp-foundation-evidence.md`;
    - report the number of roles at 200 MCPs.

## Gates

The README's gates, plus:
- the acceptance and `bun run infra:test`, each alone;
- the benchmark, run three times.

## Must not touch

- Organisation isolation.
- The schema per MCP.
- The shared database's name.
- The Secrets' names and keys.
- The `own` mode's behaviour.
