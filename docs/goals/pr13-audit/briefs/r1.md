   - Follow the MCP servers' pattern (`TOOLBOX_HOST`): add `ID_HOST` to ID's definition, with fallback `127.0.0.1` and `source: "image"`. Then set `ID_HOST=0.0.0.0` in `apps/id/Dockerfile`, beside `PORT`.

   - Keep the committed development secrets (typed configuration's D2 stands).

   - Regenerate the inventories with `bun run env:inventory`.
2. **C3: readiness depends on the server and its own database only.**

   - Readiness answers 200 when the server's own database answers. It still lists each MCP database's state in the body, without failing on it.

   - R2 deletes the standalone server, so fix the shared function and the Toolbox, and don't polish standalone-only code.
3. **F18: the test gate holds at 200 MCPs.**
   - `mcp:test` uses `bun run --filter`, which has no concurrency limit. At 100 generated MCPs one suite is refused with `too many clients` (measured; `../findings.md`, F18).
   - Run the MCP suites with a concurrency cap; Turborepo's `--concurrency` is the expected way. CI keeps calling `bun run mcp:test`.
   - Choose the cap from measurement, and say how you handled Turborepo's cache for test tasks.
   - Prove it with 100 and with 200 generated MCPs. Adapt `scratchpad/pr13-audit/X/run.sh`, which makes MCPs in a copy and drops them with `forget()`, to run the real `mcp:test` in the copy. Report the time and peak connections for today's suites and for 200 MCPs.
