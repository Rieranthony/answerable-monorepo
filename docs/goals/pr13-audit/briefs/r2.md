# R2: standalone MCPs served from the Toolbox's process (D-1)

Read [`README.md`](README.md) first, then D-1 in [`../decisions.md`](../decisions.md).

**Goal.** One serving process. The Toolbox serves its hub at `/mcp` and every `standalone` or `both` MCP at `https://mcp.<zone>/<name>/mcp`. The standalone server, and everything that exists only to run it, is gone. A person and staff see the same URLs, sign-in, clients and admin tools as before.

**Model.** Opus 5.5.

**Read:**
- C1, C2 and C11 (`../audits/C.md`);
- E1, E2, E6 and E11 (`../audits/E.md`);
- B7 (`../audits/B.md`);
- F16 (`../audits/F.md`);
- the MCP CLI's D2, D6 and D14 (`docs/goals/mcp-cli/decisions.md`);
- `mcps/standalone`, `mcps/toolbox` and `packages/mcp-platform` in full.

## What to build

1. **The Toolbox serves standalone MCPs.**
   - For each mounted MCP whose `serve` is `standalone` or `both`, a `createMcpServer` at `/<name>/mcp`, with resource `<origin>/<name>/mcp` and its protected-resource metadata path, as `mcps/standalone/src/standalone.ts` builds them today.
   - The origin is a Toolbox variable that replaces `STANDALONE_ORIGIN`.
   - The hub stays at `/mcp`. Decide whether requests are routed by path alone or by host too, and test that the hub and each standalone MCP refuse a token for another resource.
   - One generated list (`mounted.generated.ts`) carries each MCP's `serve`. Delete `served.generated.ts`, and change `scripts/mcp/generate.ts` to match.
2. **One database for the process.**
   - A standalone MCP's intents and evidence go in `answerable_toolbox`.
   - The Toolbox's single MCP pool serves every MCP; its serving login is `answerable_mcps_toolbox`.
   - Delete:
     - `answerable_standalone` and `answerable_standalone_test`;
     - the logins `answerable_standalone_owner`, `answerable_standalone_runtime` and `answerable_mcps_standalone`;
     - `infra/postgres/init/007`;
     - the bootstrap's standalone entries.
   - Own-mode MCPs keep working (D-2).
3. **One machine client.**
   - The Toolbox's `toolbox-hub` reads profiles for standalone MCPs too. Delete `standalone-hub` from register, the chart, the ops Role and the docs.
   - Standalone MCPs keep their resources and `claude-code-<name>` clients, with the same rows and the same idempotency keys.
4. **One migration Job.**
   - The Job that migrates every MCP moves out of `mcps/standalone`, into the Toolbox's workspace (C11).
   - It merges with `toolbox-migrate` into one Job that migrates the Toolbox's database and every MCP (E6).
   - Delete `standalone-migrate`, keeping the hooks' weights in order.
5. **The chart.**
   - Delete `standalone.yaml`, its values, its network policy, its Secrets in the ops Role and the zero-replica start entry.
   - The `mcp.<zone>` Ingress routes to the Toolbox's Service. The Terraform hostname and certificate stay.
   - Update `charts.test.ts`. Re-measure the release size at 200 MCPs.
6. **The admin MCP.**
   - `standalone_enable` stays.
   - `ADMIN_STANDALONE_ORIGIN` becomes required, keeping the local default (E11).
   - Drop `hostClientIds` from the tool's input only if no caller outside tests passes it. `scripts/mcp/local-access.ts` passes it to the shared plan, so check the tool and the plan separately.
7. **The CLI.**
   - `bun mcp dev` starts the Toolbox only.
   - Delete `standalone:dev`. `bun mcp list` prints the same URLs.
   - The ports table in `AGENTS.md` frees 47510, unless a scaffolded MCP still uses it.
8. **The kind stack and the acceptance.**
   - The standalone proofs now run against the Toolbox's process:
     - a person signs in at `/<name>/mcp` through `claude-code-<name>`;
     - `standalone_enable`;
     - an unenabled organisation is refused.
   - `packages/acceptance/src/standalone.ts` and `infra/k8s/local/standalone-sign-in.ts` change or go.
   - The smoke test still checks each standalone path.
9. **Delete `mcps/standalone`**, after moving what C11 moves, and the test databases and prefixes that existed for it (F16).
10. **Docs:**
    - `servers.mdx`, `sign-in.mdx`, `deploy.mdx`, `index.mdx`, `local-testing.mdx`, `docs/toolbox/*`, `docs/admin/*`;
    - `AGENTS.md`, `README.md`, `docs/12-deployment.md`, `infra/README.md` (including E13's "first ship with the standalone server" section), `charts/answerable/README.md`;
    - a note under the MCP CLI's D2 saying D-1 reversed the separate process.

## Gates

The README's gates, plus `bun run infra:test` and the acceptance, each alone.

## Must not touch

- The URLs a person uses.
- The sign-in model.
- `standalone_enable`'s behaviour.
- The ID rows register writes, and their keys.
- The per-MCP role model, which R3 replaces.
- The `own` mode's behaviour.
