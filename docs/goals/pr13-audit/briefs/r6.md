# R6: the final pass

Read [`README.md`](README.md) first.

**Goal.** The tree that merges is proven end to end, and the evidence is recorded. The coordinator runs this pass; a fresh agent does the newcomer read.

**Model.** The coordinator, with one fresh agent for the newcomer read.

## Steps

1. **Every gate, on the final tree:**
   - the README's gates;
   - `bun --filter @answerable/id test:coverage`;
   - the acceptance, alone;
   - `bun run infra:test`, alone.
2. **The end-to-end proof, from a clean copy:**
   - `bun mcp new` without a terminal, three times: one MCP served `toolbox`, one `standalone`, and one `both` with `--database own`;
   - `add tool` for a read and a mutation on each;
   - `bun mcp check` on each;
   - the kind stack from the copy, where a person signs in at each path and through the Toolbox;
   - afterwards, nothing of them remains in any Postgres, in Docker, or in the worktree.
3. **The numbers, again:**
   - the 200-MCP benchmark;
   - the test gate with 100 and 200 generated MCPs;
   - the Helm release size at 200 MCPs.

   Compare each with M9's numbers and the audit's.
4. **The newcomer read.** A fresh agent, given only the docs at `/docs/mcp`, makes, tests and ships an MCP in a copy. It reports every step it could not follow.
5. **The audit's verification:** every finding the owner approved is done or explained, in `../progress.md`.
6. **The evidence:** a dated section in `reports/mcp-foundation-evidence.md` covering:
   - what the audit changed;
   - the gates with counts and times;
   - the numbers against M9's;
   - the lines removed and added.
7. **The pull request:** a title and description covering typed configuration, the MCP CLI goal and the audit.
8. **The owner's items, listed for them:**
   - the by-hand Claude Code sign-in to a CLI-made MCP on their local ID;
   - Civo's `max_connections` before the first staging tag;
   - GHCR visibility of `answerable/mcps` once;
   - deleting the old `answerable/toolbox` and `answerable/admin-mcp` packages;
   - the merge.
