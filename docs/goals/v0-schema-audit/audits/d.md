# Audit D: Better Auth fit, revisions, identity guards and the migration reset

Auditor D (Opus 5.5), 19 October 2026. Tree: main 9833960 in a fresh worktree (`bun install --frozen-lockfile`). Postgres `audit-pg-d` (PostgreSQL 17.9, port 47436); I raised `pg_stat_statements.max` to 20,000 and `track` to `all` and restarted the container for probe 05. Probes in `$S/probes/d/` (`$S` = the session scratchpad). Host load during the runs: 4.6 to 10.4 (`uptime`); timings are on/off deltas. Nothing committed; every spike edit was reverted (`git status` clean at the end).

## 1. Summary

1. **Column census (180 columns, 15 tables).** Nine columns have no reader on a reachable route and can go: `accounts.password`, `accounts.scope` (never written), `accounts.access_token`, `accounts.id_token`, `accounts.access_token_expires_at` (written on every sign-in, read by nothing but the custody preflight), `jwks.expires_at` (never written under ID's config), `oauth_clients.require_pkce` (always true; the plugin defaults to true), `oauth_clients.response_types` (derived from `grant_types`; only the unreachable registration route reads it), `oauth_clients.contacts` (echo only). Dropping them broke no sign-in, link, consent, token or erasure test (probes 09 and 10: 534 pass; the 15 failures assert the dropped values or write them in fixtures). Everything else is written or read on a reachable route; a negative control (probe 11) shows the plugin fails loudly when a column it writes is dropped (120 of 150 user-OAuth tests).
2. **A latent bug.** The admin API accepts `signingAlgorithm` `ES256` or `RS256` on a resource, but ID provisions only an EdDSA key: every token for such a resource answers `500 authentication_unavailable` (probe 08). Delete `oauth_resources.signing_algorithm` and the field.
3. **`users.status = 'inert'`** has no writer; only the column default produces it. Delete the value and the default, so an insert without a status fails `NOT NULL` (fail-closed, louder than `inert`).
4. **Revisions, versions, ETags: keep.** All nine `revision` columns back an `If-Match` route; consumers send it on four (organisations, SSO provider, group members from the admin MCP; resources from the Toolbox), every user-token decision records them, and `sso_providers.revision` binds sessions and grants. `xmin` cannot replace them: Better Auth's provider lock on every sign-in changes `xmin` and keeps `revision` (probe 12). The revision trigger costs 13 to 19 µs per update (probe 06). `authorization_version` is a token claim the admin API and the Toolbox check: keep.
5. **Identity guards versus column grants.** Column-level `UPDATE` grants hold every identity invariant for the runtime role on PostgreSQL 17 (probe 04: 22 of 22 refusals; triggers still bump `revision` and `authorization_version`). The statement census of the full suite (probe 05) finds one app statement that would break: the group-member upsert sets `organization_id` and `member_id` to themselves (42501 even without a conflict, probe 04b). Grants bind only the runtime role, not the owner. Verdict: simplify, optionally, as one change set (three functions and three triggers deleted, four functions shortened, one upsert rewritten, a startup check of column privileges). Removing the guards fails exactly 8 of 1,564 tests, all owner-run proofs of the guards in five files (probe 14); no test proves the member identity guard.
6. **Migration reset.** `db:regenerate` round-trips ("unchanged"), `test:migrations` and the migration tests pass on 47436; the full suite passes (1,564/0, 341 s). Squash mcp-postgres's two files into one `0001_initial.sql` (identical catalogue, 76 items, probe 13). ID refuses an old database by name (probe 15); the MCP migrator refuses it only through `relation "evidence_payloads" already exists`. `0001_snapshot.json` equals `0000_snapshot.json` apart from its ids: keep both. Procedure in section 7.

## 4. Considered and kept

- **Every plugin-written column.** `checkMissingFields` refuses a create that names a column the Drizzle schema lacks (`drizzle-adapter/dist/index.mjs:251-265`), and `transformInput` names every field given a value or a default (`core/dist/db/adapter/factory.mjs:109-139`). Probe 11 shows the failure. Updates differ: Drizzle silently drops unknown keys, which is why the sign-in token columns can go.
- **Revisions on all nine tables** and `"id:revision"` ETags: four consumer routes, decision evidence, provider binding; the cost is negligible.
- **`authorization_version`**: a different event from `revision` (security transitions, not renames); tokens carry it.
- **`touch_client_resource_revision`**: correct HTTP, fires only on link changes.
- **`system_bindings`, `verifications`, `oauth_client_assertions`**, the missing `updated_at` on two tables, the normalisation CHECKs, `try_uuid`.
- **`drizzle/meta`**: both snapshots stay.

## 5. Open questions

1. **Identity guards to grants.** Worth one change set before v0, or after? Gains: three functions and three triggers deleted, four shortened (about 70 lines of reviewed SQL), new columns immutable to the runtime role until granted. Costs: one upsert rewrite, a column-privilege list in `configureRuntimeRole` (it grants table `UPDATE` on every migration), a startup check, and the 8 owner-run tests of probe 14 moved to the runtime role. The coordinator should weigh against audit B's privilege findings.
2. **DPoP.** The token endpoint honours a DPoP proof that discovery hides and `@answerable/auth` refuses. Refuse DPoP at the token endpoint until the backlog item lands (then drop both `confirmation` columns), or keep? Settle with a test that sends a DPoP proof to the token endpoint and calls the Toolbox with the result.
3. **`claims` requests.** No test drives an OIDC `claims` request through code exchange and refresh, so `requested_user_info_claims` on token rows is written by no test. One test would prove the reachable path.
4. **Refresh reuse interval.** `OAUTH_REFRESH_REUSE_INTERVAL_SECONDS` is 0 everywhere deployed: a host that refreshes twice at once loses the whole family. Not verified with a real host; settle with the acceptance (Claude Code refreshing in parallel).
5. **`users.image`** is written only when the IdP sends `picture`; not verified against Entra or Google here.
