## What it does

1. **Identity broker.** Connect your organisation's Microsoft Entra ID or Google Workspace directory once.
2. **Login provider for applications.** Apps use [OpenID Connect](/docs/id/oauth) with a stable global user ID and selected organisation.
3. **Authorisation server for services.** [OAuth grants](/docs/id/oauth) bind one approved client/resource pair to a current membership.

## Who it is for

**IT admins.** Give admin consent once. You do not need a registration for each app or client secrets to rotate.

**Organisation admins.** Read your organisation's members, groups, access and audit log through the [admin API](/docs/id/manage); changes beyond members: [Not yet.](/docs/id#today-and-next)

**Answerable staff.** Administer organisations, users and access through the same API with platform scopes: [Onboard an organisation](/docs/id/onboard).

**People at client organisations.** Sign in with the work account you already have. Guest and personal accounts are refused.

**Developers.** [Connect an application](/docs/id/oauth) using discovery, PKCE, code exchange and refresh. Each external application and resource server needs its own integration acceptance.

## The one rule

`sub` is the only identifier to join on. Email is display data.

## Today and next

| Order | Capability                                                                                                                                                                                                                                          |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Today | Organisation sign-in through your identity provider, sessions, health endpoints, the admin API (platform and tenant reads, member management, summaries and sign-in diagnosis), machine access with client credentials, and tenant-bound user OAuth |
| Next  | Real consumer and first-deployment acceptance; broader self-service and remote lifecycle work remain planned                                                                                                                                        |

**Not yet:** dynamic client registration, upstream directory polling and downstream logout delivery. Local tests do not certify real tenant, consumer or deployment behaviour.

## Endpoints

Examples use `https://id.answerable.org`; replace it with your installation's issuer. Answerable ID has not yet been deployed to production.

| Endpoint             | Purpose                                       |
| -------------------- | --------------------------------------------- |
| `/auth`              | Better Auth sign-in and session routes        |
| `/auth/oauth2/token` | Code exchange, refresh and client credentials |
| `/api/admin/v1`      | [Admin API](/docs/id/admin-api)               |
| `/healthz`           | Liveness                                      |
| `/readyz`            | Readiness                                     |

Start an organisation sign-in from the [sign-in page](https://answerable.org/login), or read [how sign-in works](/docs/id/sign-in).
