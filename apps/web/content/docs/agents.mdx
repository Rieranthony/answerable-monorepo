Every page of these docs is Markdown for agents, with the type tables and the code from the repository written out. The prompts below give a coding agent, such as Claude Code, a job, the pages to read and the commands that prove it is done. Replace the words in angle brackets.

## Build an MCP server

```text
In the Answerable monorepo, build an MCP named <name> that <what it does>, with bun mcp and @answerable/mcp.

Read first: AGENTS.md, then https://www.answerable.org/docs/mcp/quickstart.md, https://www.answerable.org/docs/mcp/tools.md and https://www.answerable.org/docs/mcp/mutations.md. mcps/example is a finished MCP made with the same commands.

1. Run `bun mcp new <name> --description "<what it is for, 40 to 1,000 characters>" --serve toolbox`.
2. For each read, run `bun mcp add tool <name> <domain.operation> --description "<what it does, when to use it, its limits>"`; for each change, add `--mutation` and say "prepare" in its description.
3. Change each tool's file and its table in src/db/schema.ts to the real data, then run `bun mcp db <name> generate`. Every table keeps organisation_id and its organisationIsolation policy. prepare returns a preview and changes nothing; commit applies exactly that.
4. Throw ToolError for expected failures, and list any custom code in the definition's errors.
5. Keep each tool's test proving that each organisation sees only its rows. Commit a mutation with the tool its intent's commit_tool names.
6. Run `bun mcp check <name>` until it passes with 100% coverage, and commit the manifest and charts/answerable/mcps.json it rewrites.

Do not add a Better Auth instance and do not read Answerable ID's database. Report the tools you made, the risk of each mutation, and the output of bun mcp check.
```

The guide it follows: [Build your first MCP](/docs/mcp/quickstart).

## Add tools to the Toolbox

```text
In the Answerable monorepo, mount the provider of mcps/<name> in the Toolbox, mcps/toolbox.

Read first: AGENTS.md and https://www.answerable.org/docs/toolbox/add-tools.md.

1. Check that `bun run mcp:check @answerable/mcp-<name>` passes.
2. Check that mcps/<name>/package.json has "exports": { "./provider": "./src/provider.ts" }, which bun mcp new writes; add it otherwise.
3. Add "@answerable/mcp-<name>": "workspace:*" to the dependencies of mcps/toolbox/package.json, import the provider in mcps/toolbox/src/server.ts and add { provider } to the mount passed to createToolbox.
4. Run `bun install`, then `bun run mcp:check @answerable/mcp-toolbox`. Its suite needs the development PostgreSQL on port 47432; never run `bun run env:up` from a worktree.
5. Write out, for staff, the enable call and the entitlement from the guide, filled in with the provider id.

Change nothing else in the Toolbox. Report the diff and the output of both checks.
```

The guide it follows: [Add tools to the Toolbox](/docs/toolbox/add-tools).

## Review a server against the standard

```text
Review mcps/<name> against the Answerable MCP design standard.

Read first: https://www.answerable.org/docs/mcp/standard.md and https://www.answerable.org/docs/mcp/tools.md.

Run `bun run mcp:check @answerable/mcp-<name>`: the conformance kit checks the rules marked Kit and SDK. Then, for each rule marked Review, say whether the server meets it, with the file and line that shows it, and what to change if it does not. Change no code.
```

The rules it checks: [MCP design standard](/docs/mcp/standard).

## How agents read these docs

| Ask for | You get |
| --- | --- |
| `https://www.answerable.org/docs/<page>.md` | One page as Markdown |
| Any docs URL with `Accept: text/markdown` | The same, at the page's own URL |
| `https://www.answerable.org/llms.txt` | Where to start, then an index of every page with its description |
| `https://www.answerable.org/llms-full.txt` | Every page in one file: 1.9 MB, most of it the API reference's operations |

**Give an agent the page for its job**, not the whole set: the pages above link to the ones they need. Each page on the site has **Copy Markdown** and **View as Markdown** buttons under its title.

**The repository has its own rules.** `AGENTS.md` at the root holds the commands, the ports, the gates and what never to do, and `CLAUDE.md` loads it for Claude Code. An agent working in the repository reads it first.

**The Markdown is generated from the source.** Type tables come from the TypeScript types and their doc comments, and code comes from files that are typechecked and tested, so an agent reads what the code does today.
