```sh
bun run mcp:test:e2e
```

Run this from the monorepo after installing [the local test requirements](/docs/mcp/local-testing). It signs three organisations into the e2e MCP through real Answerable ID, with the official MCP SDK's OAuth client and a real browser.

## Status

**Local foundation:** implemented and tested. `@answerable/mcp` defines read tools, [prepared mutations](/docs/mcp/authoring#mutations) and providers, serves them on the official MCP TypeScript SDK, answers every tool failure with one [error envelope](/docs/mcp/errors), exports each provider's contract as a manifest, and checks a provider against the standard with [the conformance kit](/docs/mcp/testing). A mutation is prepared first, which records an intent and changes nothing, then committed through a commit tool. `@answerable/auth` verifies Answerable ID access tokens. `mcps/e2e` is the reference server: three read tools, `records.create` and `records.delete`. Every export is in the [API reference](/docs/mcp/reference).

**The Toolbox:** [`mcps/toolbox`](/docs/mcp/toolbox) is one MCP endpoint that serves each person the capabilities their organisation granted them. It reads grant strings from ID's member access view with a 60-second cache and an audit-log poller, holds the catalogue, lists `toolbox_whoami` and the granted tools directly, records every call in a hash-chained evidence log and as a span, and mounts the e2e provider. Its journeys run against real ID.

**Not yet:** human approvals, operations for long work, a Postgres intent store, and the Toolbox's meta tools, `list_changed` and administration API.

**External hosts:** Claude Code connects with a pre-registered client; see [Connect Claude Code](/docs/mcp/claude-code). Claude.ai and hosted deployment: Not yet.

## How a request is authorised

1. The host posts to the MCP endpoint. The server refuses a foreign `Host` or browser `Origin`.
2. Without a valid token, the server answers `401` with `WWW-Authenticate: Bearer resource_metadata="…"`. The host reads the [protected-resource metadata](https://datatracker.ietf.org/doc/html/rfc9728), discovers Answerable ID and signs the person in with PKCE and the MCP's URL as `resource`.
3. The server verifies the token against ID's published keys: issuer, audience (the MCP's URL), type `at+jwt`, expiry and the user and organisation claims.
4. The server registers only the tools, prompts and resources whose scopes the token carries, and the commit tools when it can use at least one mutation, then answers in the host's protocol version (`2026-07-28`, or 2025 for older hosts). A tool failure is a result carrying the [error envelope](/docs/mcp/errors), not a protocol error.
5. A commit applies an intent only for the person, membership and client that prepared it, with its single-use token, before it expires and while its targets are unchanged.

The MCP never sees a password, never runs Better Auth and never reads ID's database.

## Packages

| Package | Responsibility |
| --- | --- |
| `@answerable/auth` | Verify an Answerable ID access token for any service |
| `@answerable/auth/testing` | An in-process issuer that signs test tokens |
| `@answerable/mcp` | `defineTool`, `defineMutation`, `defineProvider`, `definePrompt`, `defineResource`, `defineView`, `createMcpServer`, `createMemoryIntentStore`, `manifest`, `ToolError`, `readMcpEnvironment` |
| `@answerable/mcp/build` | Bundle an MCP Apps view into one HTML resource |
| `@answerable/mcp/testing` | `createTestMcp`: serve a provider, or a hub, in-process with the official MCP client. `assertProviderConformance`: the conformance kit |
| `@answerable/mcp-toolbox` | The Toolbox: `createToolbox`, the grants reader and poller, the catalogue, evidence and spans (`mcps/toolbox`) |

Views import the official MCP Apps browser API, `@modelcontextprotocol/ext-apps`, directly.

## Limits

**Partial entitlements.** ID issues the entitled subset of the requested scopes. The MCP lists only the tools, prompts and resources the token's scopes cover.

**Revocation.** The MCP verifies tokens offline, so a disabled organisation's issued access token works until it expires; refresh stops at once. Keep resource token lifetimes short.

**Client registration.** Hosts use a client registered in ID ahead of time. Dynamic registration and client ID metadata documents: Not yet.
