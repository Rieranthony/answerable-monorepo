```ts
import { createMcpApp, defineTool, readMcpEnvironment } from "@answerable/mcp-base"
import { z } from "zod"

const identityGet = defineTool({
  name: "identity_get",
  description: "Read your authenticated organisation",
  input: z.object({}).strict(),
  output: z.object({ organizationId: z.uuid() }),
  scopes: ["example:read"],
  annotations: { readOnlyHint: true, openWorldHint: false },
  async execute(_input, context) {
    return {
      data: { organizationId: context.principal.organizationId },
      text: "Authenticated with Answerable ID",
    }
  },
})

const { auth, port } = readMcpEnvironment(process.env)
const app = createMcpApp({ name: "example", version: "0.1.0", auth, services: {}, tools: [identityGet] })
Bun.serve({ hostname: "127.0.0.1", port, fetch: app.fetch })
```

Save this as `mcps/example/src/server.ts`. `createMcpApp` returns a web-standard `{ fetch }` handler; the entry point owns the listener.

## Create a workspace

```json
{
  "name": "@answerable/mcp-example",
  "private": true,
  "type": "module",
  "scripts": { "dev": "bun --hot src/server.ts", "start": "bun src/server.ts" },
  "dependencies": { "@answerable/mcp-base": "workspace:*", "zod": "4.6.5" }
}
```

Save this as `mcps/example/package.json`, then run `bun install` from the repository root. The `mcps/*` workspace pattern includes it.

## Configure

```dotenv
MCP_ID_ISSUER=http://localhost:47300
MCP_RESOURCE_URL=http://localhost:47500/mcp
MCP_PORT=47500
```

`readMcpEnvironment(process.env)` reads these three variables and returns `{ auth, port }`.

**Issuer.** The Answerable ID origin. The verifier reads ID's signing keys from the issuer's metadata; never take an issuer from a token.

**Resource.** The MCP's canonical URL, exactly as registered in ID. It is the token audience, and its path is the MCP endpoint.

**HTTP.** Both URLs must use HTTPS, except on `localhost`, `127.0.0.1` or `[::1]`.

Register the resource, a client and its access in ID before the first sign-in; see [Connect Claude Code](/docs/mcp/claude-code#register-the-server). Each MCP running at the same time needs its own port.

## Tools

`defineTool` takes `name`, `description`, Zod `input` and `output` objects, `scopes`, optional `title`, `annotations` and `view`, and `execute(input, context)`. `execute` returns `data` (checked against `output`) and `text` for hosts that ignore structured content.

**Scopes decide visibility.** A token lists only the tools whose every scope it carries. A tool it cannot use is absent from `tools/list`, and calling it returns the protocol's unknown-tool error.

**Context.** `context.principal` holds `userId`, `organizationId`, `membershipId`, `grantId`, `clientId`, `scopes` and `expiresAt`. `context.services` is what you passed to `createMcpApp`. `context.signal` aborts when the host cancels or disconnects. Constrain every query by `principal.organizationId`.

**Errors.** Throw `new ToolError(code, message)` for a safe, expected failure. Any other exception returns `tool_failed` without its message.

## Prompts and resources

`definePrompt` takes `name`, `description`, a Zod `input`, `scopes` and `execute(input, context)`, which returns an MCP prompt result. `defineResource` takes `name`, a fixed `uri`, `description`, `mimeType`, `scopes` and `read(context)`, which returns text. Both follow the same scope rule as tools. Reading a prompt or resource must not change data.

## Views

```ts
import { buildView } from "@answerable/mcp-base/build"

const html = await buildView({ entry: "src/views/records.tsx", title: "Records" })
```

Build each view before starting the server, pass the HTML to `defineView({ name, html })`, and set the view on a tool. The base registers it as a `ui://` resource with the MCP Apps MIME type. Browser code imports `useApp` from `@modelcontextprotocol/ext-apps/react` or `App` from `@modelcontextprotocol/ext-apps`. A view calls tools through the host, with the same scope and organisation checks; it never receives a token. `mcps/e2e` is the working example.

## Health

`GET /health` returns `{ "status": "ok" }` without authentication.

## Errors

| Error | Meaning | What to do |
| --- | --- | --- |
| `401 invalid_token` | Missing, expired or foreign token, or a token for another MCP | Sign in through ID for this MCP's resource URL |
| `403` on the MCP endpoint | The `Host` or browser `Origin` is not allowed | Call the MCP by its registered host name, or set `allowedHosts` / `allowedOrigins` |
| Unknown tool, prompt or resource | Not defined, or the token lacks its scopes | Check the token's scopes against the definition |
| Tool result `tool_failed` | Unexpected handler failure or invalid output | Read the server logs |
| Tool result with your code | A `ToolError` you threw | Handle the code |
| `Invalid MCP configuration: …` at start | A missing or invalid variable | Set the named variable |
