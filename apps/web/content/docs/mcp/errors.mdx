```json
{
  "error": {
    "code": "INTENT_STALE",
    "message": "Intent 0199a4e2-7b06-7000-87bd-91723fe45f93 is stale: “Q3 plan” changed since it was prepared; prepare it again",
    "retry": { "policy": "after_reprepare" },
    "details": { "targets": [{ "resource_id": "d7c1", "expected": "17", "current": "18" }] },
    "request_id": "0199a4e2-8c11-7000-9a3e-5b2d6f1c0e44"
  }
}
```

Every tool failure is `{ "isError": true, "content": [{ "type": "text", "text": "…" }] }` with no `structuredContent`, and the one text block is this envelope as JSON. A model picks its next step from `retry.policy` without reading the message. Handlers throw it with [`ToolError`](/docs/mcp/authoring#tool-errors). The rules it follows are in [the design standard](/docs/mcp/standard#errors).

**Why text only.** The MCP TypeScript SDK 1.x client checks any `structuredContent` against the tool's `outputSchema`, even on an error result, so an envelope there made `callTool` throw `Structured content does not match the tool's output schema` instead of returning it. It leaves a result without structured content untouched. Measured with SDK 1.30.0, which LibreChat uses; SDK 2.x clients return both shapes. Claude Code shows the model the text of a result that has no structured content. As text, the envelope reaches the model through every one of these clients.

## The envelope

| Field | Value |
| --- | --- |
| `code` | A code from the table below, or a [custom code](#custom-codes) |
| `message` | Plain English for the model and the person. `INTERNAL` carries no detail |
| `retry.policy` | What to do next; see [retry policies](#retry-policies) |
| `retry.after_ms` | With `after_delay` only: milliseconds to wait. Default 1,000 |
| `details` | Present only when the code has details: [`field_violations`](#field-violations), [`targets`](#stale-targets), [`approval`](#approval), or your own |
| `request_id` | The call's execution id, a UUIDv7. The server log names it for `INTERNAL` |

## Retry policies

| Policy | What the caller does |
| --- | --- |
| `never` | Stop, and tell the person why |
| `after_delay` | Wait `after_ms`, then call again with the same arguments |
| `after_fix_input` | Change the input, then call again: correct the fields in `details.field_violations`, or narrow a request that answered `RESULT_TOO_LARGE` |
| `after_state_change` | Wait until what `details.preconditions` names has changed, then call again |
| `after_reprepare` | Call the mutation's prepare tool again, then commit the new intent |
| `after_approval` | Commit with the tool in `details.approval.commit_tool`. Human approvals: Not yet |

## Codes

| Code | Meaning | Retry | What to do |
| --- | --- | --- | --- |
| `INVALID_INPUT` | The input failed the schema or a business rule | `after_fix_input` | Fix the fields in `details.field_violations` |
| `NOT_FOUND` | A named resource does not exist for this caller; another organisation's resource is not found either. The Toolbox's meta tools answer it for a capability you may not use, as for one that does not exist | `never` | Check the identifier, for example with a list tool or `toolbox_search` |
| `PERMISSION_DENIED` | The caller may not perform the operation; a commit answers it too when the caller can no longer use the mutation (its token lacks the scopes, or a hub's grants no longer cover it) | `never` | Ask for access, then prepare again |
| `PRECONDITION_FAILED` | The current state does not allow the operation; `details.preconditions` says what | `after_state_change` | Change that state first |
| `RESULT_TOO_LARGE` | A read's result exceeded 100 KiB of JSON; `details.bytes` is its size and `details.limit` the limit, 102,400 bytes | `after_fix_input` | Narrow the request with `limit`, `cursor` or filters |
| `INTENT_STALE` | A target's version moved, or a target disappeared or appeared, since prepare; `details.targets` says which | `after_reprepare` | Prepare again and show the new preview |
| `INTENT_EXPIRED` | The intent passed `expires_at` before it was committed | `after_reprepare` | Prepare again |
| `INTENT_NOT_FOUND` | No intent has that id, or it is for a capability version this server does not serve | `after_reprepare` | Prepare again |
| `INTENT_CONSUMED` | The intent was committed once and that commit failed | `after_reprepare` | Prepare again |
| `INTENT_CANCELLED` | The intent was cancelled | `after_reprepare` | Not yet: intents cannot be cancelled |
| `COMMIT_TOKEN_INVALID` | The commit token does not match the intent | `never` | Pass the `commit_token` the prepare tool returned for this intent |
| `PRINCIPAL_MISMATCH` | Another person, membership or client prepared the intent | `never` | Prepare your own intent |
| `APPROVAL_REQUIRED` | The intent's class needs the other commit tool, the person's confirmed summary, or a human approval | `after_approval` | See [approval](#approval) |
| `APPROVAL_DENIED` | A person refused the approval | `never` | Not yet: approvals do not exist |
| `COMMIT_IN_PROGRESS` | Another commit of this intent is running | `after_delay` | Call again; a finished commit answers with its receipt |
| `IDEMPOTENCY_KEY_MISMATCH` | The same idempotency key came with different input | `never` | Not yet: prepare takes no idempotency key |
| `RATE_LIMITED`, `BUDGET_EXHAUSTED` | A limit refused the call | `after_delay` | Wait `after_ms`. Not yet: the SDK enforces no limits; a handler may throw them |
| `UPSTREAM_REJECTED` | The source refused; `details.upstream` carries its code | `never` | Read `details.upstream`. A handler that calls a source throws it; no Answerable provider does yet |
| `UPSTREAM_UNAVAILABLE` | The source did not answer | `after_delay` | Call again later. The Toolbox answers it when Answerable ID does not say what you may use; a handler that calls a source throws it, and no Answerable provider does yet |
| `TIMEOUT` | The tool ran past its `timeoutMs` | `after_delay` | Call again; a commit may still finish, so call the commit tool again for its receipt |
| `OPERATION_NOT_FOUND`, `OPERATION_EXPIRED` | The operation handle is unknown or gone | `never` | Not yet: operations do not exist |
| `INTERNAL` | An unexpected failure, or a handler that threw a [custom code](#custom-codes) its definition does not declare | `after_delay` | Call again once; if it persists, the operator reads the server log for the `request_id`, which names an undeclared code |

**Who answers what.** The server answers `INVALID_INPUT` for bad arguments, `TIMEOUT` and `INTERNAL` for every tool. The commit tools answer the `INTENT_*` codes, `COMMIT_TOKEN_INVALID`, `PRINCIPAL_MISMATCH`, `APPROVAL_REQUIRED`, `COMMIT_IN_PROGRESS` and `PERMISSION_DENIED`, in [this order](/docs/mcp/authoring#commit-tools). [The Toolbox](/docs/mcp/toolbox#errors) answers `RESULT_TOO_LARGE` and `UPSTREAM_UNAVAILABLE`; its meta tools answer `NOT_FOUND` for a capability you may not use and `INVALID_INPUT` for a capability sent to the wrong one of `toolbox_execute` and `toolbox_prepare`. Your handlers throw the rest with `ToolError`. `errorCodes` in `@answerable/mcp` exports the table as data ([reference](/docs/mcp/reference#errorcodes)).

## Custom codes

A provider may add its own codes, `<PROVIDER>_<CODE>` in capitals such as `ACME_QUOTA_EXCEEDED`, each with its own retry policy and listed in the `errors` of the tool that throws it; the manifest carries the list. [Tool errors](/docs/mcp/authoring#tool-errors) shows how to throw and declare one. An undeclared custom code answers `INTERNAL`.

## Field violations

```json
{ "field_violations": [{ "field": "nested.count", "message": "Invalid input: expected number, received string" }, { "field": "extra", "message": "Unknown field" }] }
```

`details` of `INVALID_INPUT`: one entry per problem. `field` is the dotted path; the top level is `""`. An unknown top-level field has the message `Unknown field`. The envelope's `message` joins them as `field: message; …`.

## Stale targets

`details.targets` of `INTENT_STALE`: one entry per target that changed since prepare.

| Field | Value |
| --- | --- |
| `resource_id` | The target's id |
| `expected` | The version `prepare` saw; `null` when the target appeared since |
| `current` | The version now; `null` when the target disappeared |

The intent stays `stale`: a later commit answers `INTENT_STALE` without `details`.

## Approval

`details.approval` of `APPROVAL_REQUIRED`: `{ "class": "controlled", "commit_tool": "e2e_commit_confirmed" }`. A human-class intent adds its approval's `"status": "pending"`; `url` is Not yet.

| Case | What to do |
| --- | --- |
| An agent-class intent sent to `<id>_commit_confirmed` | Commit it with `<id>_commit` |
| A controlled-class intent sent to `<id>_commit` | Show the person the preview, then call `<id>_commit_confirmed` with `preview_summary` |
| `preview_summary` differs from the intent's summary | Pass `preview.summary` word for word |
| A human-class intent, whichever commit tool, with `status: "pending"` | It needs a person's approval. Not yet: there is no approval page and no `approval.url`, so the intent waits as `awaiting_approval` until it expires, 24 hours after prepare |

A refused commit leaves the intent committable.

## Not tool errors

A tool the token cannot use answers the protocol's `Tool <name> not found`, never an envelope, so the tools of other scopes cannot be enumerated. Authentication answers HTTP `401`, a foreign `Host` or `Origin` HTTP `403`. See [the authoring errors](/docs/mcp/authoring#errors).

## Limits

| Limit | Value |
| --- | --- |
| Envelopes per failure | One, in the one text block |
| `after_ms` default | 1,000 |
| Custom code shape | `^[A-Z][A-Z0-9]*_[A-Z0-9_]+$`, starting with the provider's id in capitals when declared |
| `INTERNAL` message | Always `The tool could not complete` |
| `Retry-After` from a source into `after_ms` | Not yet |
