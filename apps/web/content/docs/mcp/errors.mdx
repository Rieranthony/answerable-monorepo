```json
{
  "error": {
    "code": "INTENT_STALE",
    "message": "Intent 0199a4e2-7b06-7000-87bd-91723fe45f93 is stale: “Q3 plan” changed since it was prepared; prepare it again",
    "retry": { "policy": "after_reprepare" },
    "details": { "targets": [{ "resource_id": "d7c1", "expected": "17", "current": "18" }] },
    "request_id": "0199a4e2-8c11-7000-9a3e-5b2d6f1c0e44"
  }
}
```

Every tool failure is `{ "isError": true, "content": [{ "type": "text", "text": "…" }] }` with no `structuredContent`, and the one text block is this envelope as JSON. A model picks its next step from `retry.policy` without reading the message. Handlers throw it with [`ToolError`](/docs/mcp/tools#tool-errors). The rules it follows are in [the design standard](/docs/mcp/standard#errors).

**Why text only.** The MCP TypeScript SDK 1.x client checks any `structuredContent` against the tool's `outputSchema`, even on an error result, so an envelope there made `callTool` throw `Structured content does not match the tool's output schema` instead of returning it. It leaves a result without structured content untouched. Measured with SDK 1.30.0, which LibreChat uses; SDK 2.x clients return both shapes. Claude Code shows the model the text of a result that has no structured content. As text, the envelope reaches the model through every one of these clients.

## The envelope

| Field | Value |
| --- | --- |
| `code` | A code from the table below, or a [custom code](#custom-codes) |
| `message` | Plain English for the model and the person. `INTERNAL` carries no detail |
| `retry.policy` | What to do next; see [retry policies](#retry-policies) |
| `retry.after_ms` | With `after_delay` only: milliseconds to wait. Default 1,000 |
| `details` | Present only when the code has details: [`field_violations`](#field-violations), [`targets`](#stale-targets), [`approval`](#approval), or your own |
| `request_id` | The call's execution id, a UUIDv7. The server log names it for `INTERNAL` |

## Retry policies

| Policy | What the caller does |
| --- | --- |
| `never` | Stop, and tell the person why |
| `after_delay` | Wait `after_ms`, then call again with the same arguments |
| `after_fix_input` | Change the input, then call again: correct the fields in `details.field_violations`, or narrow a request that answered `RESULT_TOO_LARGE` |
| `after_state_change` | Wait until what `details.preconditions` names has changed, then call again |
| `after_reprepare` | Call the mutation's prepare tool again, then commit the new intent |
| `after_approval` | Commit with the tool in `details.approval.commit_tool`. Human approvals: Not yet |

## Codes

<ErrorCodes />

The codes and their retry policies are read from `errorCodes` in `@answerable/mcp` when these docs build ([reference](/docs/mcp/reference#errorcodes)); a `ToolError` without `retry` gets the policy shown.

**Who answers what.** The server answers `INVALID_INPUT` for bad arguments, `TIMEOUT` and `INTERNAL` for every tool. The commit tools answer the `INTENT_*` codes, `COMMIT_TOKEN_INVALID`, `PRINCIPAL_MISMATCH`, `APPROVAL_REQUIRED`, `COMMIT_IN_PROGRESS` and `PERMISSION_DENIED`, in [this order](/docs/mcp/mutations#commit-tools). [The Toolbox](/docs/toolbox#errors) answers `RESULT_TOO_LARGE` and `UPSTREAM_UNAVAILABLE`; its meta tools answer `NOT_FOUND` for a capability you may not use and `INVALID_INPUT` for a capability sent to the wrong one of `toolbox_execute` and `toolbox_prepare`. Your handlers throw the rest with `ToolError`.

## Custom codes

A provider may add its own codes, `<PROVIDER>_<CODE>` in capitals such as `ACME_QUOTA_EXCEEDED`, each with its own retry policy and listed in the `errors` of the tool that throws it; the manifest carries the list. [Tool errors](/docs/mcp/tools#tool-errors) shows how to throw and declare one. An undeclared custom code answers `INTERNAL`. The admin MCP's `ADMIN_REAUTHENTICATION_REQUIRED`, retry `after_state_change`, is one: [Critical operations](/docs/admin#critical-operations).

## Field violations

```json
{ "field_violations": [{ "field": "nested.count", "message": "Invalid input: expected number, received string" }, { "field": "extra", "message": "Unknown field" }] }
```

`details` of `INVALID_INPUT`: one entry per problem. `field` is the dotted path; the top level is `""`. An unknown top-level field has the message `Unknown field`. The envelope's `message` joins them as `field: message; …`.

## Stale targets

`details.targets` of `INTENT_STALE`: one entry per target that changed since prepare.

| Field | Value |
| --- | --- |
| `resource_id` | The target's id |
| `expected` | The version `prepare` saw; `null` when the target appeared since |
| `current` | The version now; `null` when the target disappeared |

The intent stays `stale`: a later commit answers `INTENT_STALE` without `details`.

## Approval

`details.approval` of `APPROVAL_REQUIRED`: `{ "class": "controlled", "commit_tool": "e2e_commit_confirmed" }`. A human-class intent adds its approval's `"status": "pending"`; `url` is Not yet.

| Case | What to do |
| --- | --- |
| An agent-class intent sent to `<id>_commit_confirmed` | Commit it with `<id>_commit` |
| A controlled-class intent sent to `<id>_commit` | Show the person the preview, then call `<id>_commit_confirmed` with `preview_summary` |
| `preview_summary` differs from the intent's summary | Pass `preview.summary` word for word |
| A human-class intent, whichever commit tool, with `status: "pending"` | It needs a person's approval. Not yet: there is no approval page and no `approval.url`, so the intent waits as `awaiting_approval` until it expires, 24 hours after prepare |

A refused commit leaves the intent committable.

## Not tool errors

| You see | Meaning | What to do |
| --- | --- | --- |
| `Tool <name> not found` | Not defined, or the token lacks its scopes. It is a protocol error, never an envelope, so the tools of other scopes cannot be enumerated | Check the token's scopes against the definition |
| HTTP `401` with `invalid_token` | Missing, expired or foreign token, or a token for another MCP | Sign in through ID for this MCP's resource URL |
| HTTP `403` on the MCP endpoint | The `Host` or browser `Origin` is not the resource URL's host name | Call the MCP by its registered host name |
| HTTP `500`, logged as `[mcp] request failed` | A hub's `allow`, `project` or `policyClass` threw something other than a `ToolError`, such as a failed database read | Read the error in the server log. The same line logs requests the SDK refuses, such as an unsupported protocol version or a `Content-Type` that is not JSON |
| `INTERNAL`, logged as `[mcp] tool <name> failed` | Unexpected handler failure, or output that does not match `output` | Read the server log for the `request_id`; a commit tool logs under its wire name |
| `INTERNAL` from a prepare tool, logged with `Mutation …: the preview names effects it does not declare…` | The preview names an effect missing from `effects` | Declare it in `effects`, or leave it out of the preview |
| `INTERNAL` from a prepare tool, logged with a Zod error | The plan breaks its shape: no summary, a summary over 500 characters, a target without a version | Return the shape in [the preview](/docs/mcp/mutations#the-preview) and [targets](/docs/mcp/mutations#targets-and-versions) |
| `INTERNAL`, logged as `… threw ACME_…, which its definition does not declare; add it to errors` | The handler threw a custom code missing from `errors` | Add the code to the definition's `errors` |
| A conformance test fails | A definition breaks a rule of the standard | See [Test an MCP](/docs/mcp/testing#errors) |

## When a definition is refused

These throw when the module loads, so the server never starts with a broken definition.

| Message | Meaning | What to do |
| --- | --- | --- |
| `Tool name "…" must be <domain>.<operation>…` | The name breaks the naming rule; a mutation says `Mutation name` | Rename it, for example `notes.list` |
| `Tool …: the description is N characters…` | Shorter than 40 or longer than 1,000; a mutation says `Mutation …` | Say what it does, when to use it and its limits |
| `Tool …: timeoutMs … must be a whole number of milliseconds from 1 to 55,000` | The timeout is out of range | Use at most 55,000 |
| `Mutation …: risk "…" must be low, normal or high` | Another value | Use one of the three, or omit it for `normal` |
| `Mutation …: effect "…" is not in the vocabulary…` | An effect outside the six | Use a name from the vocabulary |
| `Mutation …: expiresInMs … must be a whole number…; a mutation may shorten its expiry, not lengthen it` | Longer than the expiry its `risk` gives, or not a whole number | Shorten it, or omit it |
| `…must be a date, YYYY-MM-DD` | A version or deprecation date is not a calendar date | Write the date as `YYYY-MM-DD` |
| `…scopes must be non-empty and contain no spaces…` | An empty scope list or a scope with a space | Omit `scopes` for the default, or fix the list |
| `Provider id "…" must be a lowercase letter…` | The id breaks the rule | Use up to 12 lowercase letters or digits, starting with a letter |
| `Provider … defines tool … twice` | Two definitions share a tool name, prompt name or resource URI | Rename one |
| `Provider … defines two different views at …` | Two views share a name | Share one `defineView` result, or rename a view |
| `Provider …: tool … is deprecated in favour of …, which is not a current tool of this provider` | The replacement is missing or itself deprecated | Name a current tool of the provider |
| `View name "…" must be…`, `Prompt name "…" must be…`, `Resource name "…" must be…` | The name breaks its rule | Rename it as the message shows |
| `View …: the HTML is empty…` | The view was not built | Build it with `buildView` before `defineView` |
| `Resource …: uri "…" must be an absolute URI…`, `Resource …: … is a ui:// view…` | The URI is relative, or it is a view's | Use an absolute URI such as `fixture://guide`; define a view with `defineView` |
| `Views must bundle to one script and optional CSS…` | The view imports a file that the bundler emits on its own | Embed it in the script or the CSS |
| `Provider … is mounted twice…` | A hub mounts one provider twice, or mounts its own provider | Mount each provider once |
| `ToolError code "…" must be a standard code or <PROVIDER>_<CODE>…` | The code is not in the table and has the wrong shape | Use a standard code, or `ACME_SOMETHING` |
| `ToolError code "…" is not in the standard table; pass { retry }…` | A custom code without a retry policy | Pass `{ retry: { policy } }` |
| `Tool …: errors entry "…" must be a custom code…` | An entry in `errors` is a standard code, or not `<PROVIDER>_<CODE>` in capitals; a mutation says `Mutation …` | Remove standard codes; write custom ones as `ACME_QUOTA_EXCEEDED` |
| `Provider …: … declares error "…"; a custom code of this provider starts with …_` | A declared code does not start with the provider id in capitals | Rename it, for example `ACME_QUOTA_EXCEEDED` in provider `acme` |
| `Invalid MCP configuration: …` at start | A missing or invalid variable | Set the named variable; see [Configure](/docs/mcp/servers#configure) |
| `Server name "…" must be a lowercase letter then up to 11 lowercase letters or digits…` from `mcp:new` | The name is not a provider id | Use a name such as `acme` |
| `mcps/<name> already exists; choose another name or remove it` from `mcp:new` | The directory exists | Choose another name, or remove the directory |
| `…/manifest.json is out of date; regenerate it with UPDATE_MANIFEST=1…` | The manifest differs from the code, or has not been written yet | Run `UPDATE_MANIFEST=1 bun run --filter @answerable/mcp-<name> test`, review the diff and commit |

## Limits

| Limit | Value |
| --- | --- |
| Envelopes per failure | One, in the one text block |
| `after_ms` default | 1,000 |
| Custom code shape | `^[A-Z][A-Z0-9]*_[A-Z0-9_]+$`, starting with the provider's id in capitals when declared |
| `INTERNAL` message | Always `The tool could not complete` |
| `Retry-After` from a source into `after_ms` | Not yet |
