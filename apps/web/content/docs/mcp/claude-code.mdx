title: Connect Claude Code
description: "Connect Claude Code to the Toolbox, to an MCP at its own path or to the admin MCP, sign in through Answerable ID and see the tools your organisation granted. bun mcp registers them on your machine, and the register Job in a deployment."
---

```bash
claude mcp add --transport http answerable-toolbox http://localhost:47400/mcp \
  --client-id claude-code-toolbox --callback-port 47700
```

Run this once the Toolbox is running and your organisation is enabled for it ([below](#the-toolbox)). Then open Claude Code, run `/mcp`, select `answerable-toolbox` and choose **Authenticate**. Your browser opens Answerable ID: sign in with your work account, choose the organisation and accept. A local ID needs a sign-in for your email domain first: [Before you start](/docs/mcp/run-locally#before-you-start). Without a browser on that machine, run `claude mcp login answerable-toolbox --no-browser` in a terminal: it prints the address to open on another machine and asks you to paste back the address you are sent to. Ask Claude to call `toolbox_whoami`; it returns you, your organisation and the grants you hold. To connect the e2e server instead, see [the e2e server](#the-e2e-server).

**An MCP that has shipped.** The deploy registers it and prints these commands, and staff enable your organisation: [Your MCP's sign-in](/docs/mcp/sign-in#connect-claude-code).

**An MCP you are making.** `bun mcp dev <mcp>` registers it in your local ID, gives your organisation access and prints the command that connects Claude Code to it ([Run an MCP on your machine](/docs/mcp/run-locally)). For an MCP that runs on its own URL, the command is:

```bash
claude mcp add --transport http acme http://localhost:47400/acme/mcp \
  --client-id claude-code-acme --callback-port 47700
```

For an MCP that runs in the Toolbox it is the Toolbox's command above. Then `/mcp`, choose the connection and **Authenticate**, as above.

## The Toolbox

[The Toolbox](/docs/toolbox) serves the tools your organisation granted you, and no others.

### What you see

| Your grants | Tools Claude Code lists |
| --- | --- |
| None | `toolbox_whoami` |
| `e2e/records` | `toolbox_whoami`, the four `e2e_records_*` tools, `toolbox_commit` and `toolbox_commit_confirmed` |
| `e2e` | The above and `e2e_identity_get` |

**Writes.** Ask Claude to create a test record: it calls `e2e_records_create`, which prepares an intent and changes nothing, then `toolbox_commit`. Deleting calls `e2e_records_delete`, then `toolbox_commit_confirmed` with the preview's summary. The confirmed tool carries `anthropic/requiresUserInteraction: true`, and Claude Code 2.1.282's source asks whenever a tool has it, whatever the allow rules say. Seeing that prompt in a session: Not yet tested; [Host lane](/docs/mcp/local-testing#host-lane) has the steps.

**Changes.** An entitlement changed in ID reaches your token within 60 seconds, without signing in again. The tool list follows when Claude Code lists tools again.

### Register the Toolbox and Claude Code

Locally, `bun mcp setup`, then `bun mcp dev <name>`: [Run an MCP on your machine](/docs/mcp/run-locally). In a deployment, the register Job registers the Toolbox and `claude-code-toolbox`, and staff enable each organisation and grant it tools with `toolbox_enable` and `access_grant` in [the admin MCP](/docs/admin): [Set up the admin MCP](/docs/admin/setup). [Grant strings](/docs/toolbox#grant-strings) says what each grant covers.

## The e2e server

```bash
claude mcp add --transport http answerable-e2e http://localhost:47400/e2e/mcp \
  --client-id claude-code-e2e --callback-port 47700
```

The Toolbox serves e2e [alone](/docs/mcp/servers#served-alone), at its own path, beside its hub. Run `bun mcp dev e2e` first: it registers e2e's resource and its client, `claude-code-e2e`, gives your organisation access and prints this command. Then open Claude Code, run `/mcp`, select `answerable-e2e` and choose **Authenticate**. Ask Claude to call `identity_get`; it returns your organisation.

**Writes.** Ask Claude to create a test record: it calls `records_create`, which prepares an intent and changes nothing, then `e2e_commit`. Deleting calls `records_delete`, then `e2e_commit_confirmed` with the preview's summary. See [mutations](/docs/mcp/mutations).

### Register the server

Locally, `bun mcp setup`, then `bun mcp dev <name>`: [Run an MCP on your machine](/docs/mcp/run-locally). In a deployment, the register Job: [Set up the admin MCP](/docs/admin/setup). Both register an MCP served alone the same way:

- **Resource.** The URL is the token audience. It must be `TOOLBOX_STANDALONE_ORIGIN` and the MCP's path exactly: `localhost` and `127.0.0.1` are different resources.
- **Lifetime.** 900 seconds. Claude Code refreshes an access token that is close to expiry before using it. With a 300-second lifetime it refreshed before every request; with 900 seconds it did not. A shorter lifetime ends access sooner after a revocation, at the cost of those refreshes.
- **Public client.** Claude Code runs on your machine, so its client, `claude-code-<name>`, has no secret; PKCE protects the code. The redirect URI must match `--callback-port` exactly.
- **Every scope.** Claude Code asks for every scope the MCP lists. ID issues the ones the organisation is entitled to, and Claude Code sees only the tools they cover: without `e2e:write`, the three read tools and no commit tools. See [capabilities and entitlements](/docs/id/onboard#grant-access).

## The admin MCP

```bash
claude mcp add --transport http answerable-admin http://localhost:47520/mcp \
  --client-id claude-code-admin --callback-port 47700
```

For Answerable staff: [the admin MCP](/docs/admin) onboards and manages organisations from Claude Code, each tool behind a role read live from ID. Register it with the cURL in [Set up the admin MCP](/docs/admin/setup), or try it on your machine with the lane that registers everything for you: `bun packages/acceptance/scripts/admin-lane.ts`, described in [Try it locally](/docs/admin/setup#try-it-locally). It uses the callback port `47700`, so the Toolbox in the same session needs another, such as `--callback-port 47701`.

## Other hosts

**Claude.ai and Claude Desktop connectors.** They connect from Anthropic's servers, so they cannot reach `localhost`. Register `https://claude.ai/api/mcp/auth_callback` as the redirect URI and enter the client ID under the connector's advanced settings once the server has a public URL: Not yet tested.

**Automatic registration.** Claude Code and Claude.ai can register themselves when an authorisation server supports dynamic registration or client ID metadata documents. ID supports neither: Not yet.

## Limits

| Limit | Value |
| --- | --- |
| Claude Code against the Toolbox, with a partial entitlement (`e2e/records`) | Signing in (`claude mcp login`) and connecting were run, and the seven tools and their `_meta` were read with the same public client through the kit ([Host lane](/docs/mcp/local-testing#host-lane)). A session with a model: Not yet tested |
| Whether Claude Code asks before a confirmed commit under an allow rule | Not yet tested in a session. The Toolbox sets `anthropic/requiresUserInteraction: true` on `toolbox_commit_confirmed` and on no other tool, and the admin MCP on `admin_commit_confirmed` |
| Claude Code against the admin MCP | Signing in and the whole onboarding story were run with the kit's client for `claude-code-admin` ([the admin lane](/docs/admin/setup#try-it-locally)). A session with a model: Not yet tested |
| A partial entitlement to the e2e server in Claude Code by hand | Not yet tested |
| Client registration | A client registered in ID ahead of time; registration by the host itself: Not yet |

## Errors

| Error | Meaning | What to do |
| --- | --- | --- |
| "Access is unavailable for this organisation" | The organisation lacks a login capability or entitlement for the client, or a capability or entitlement for the server (a partial entitlement is fine: ID issues the entitled subset) | Locally, `bun mcp dev <mcp>` gives your organisation access. In a deployment, staff run `toolbox_enable` or `standalone_enable` in [the admin MCP](/docs/admin) |
| `invalid_redirect` | The callback port differs from the registered redirect URI | Use `--callback-port 47700`, or register the port you use |
| `invalid_target` | The resource is unknown, not linked to the client, or written differently | Use the exact registered URL and link it; the enable call links the Toolbox's host client |
| `invalid_client` | The client ID is unknown or disabled | Check `claude mcp get answerable-toolbox` (or `answerable-e2e`) against the registration |
| `claude mcp login`: `stdin isn't a terminal, so authentication can't be completed here` | It needs a terminal to read the redirect | Run it in an interactive terminal (`ssh -t` for a remote machine) |
| `401` after signing in | The server's issuer or resource differs from ID's | Set `TOOLBOX_ID_ISSUER` and `TOOLBOX_RESOURCE_URL`, or `TOOLBOX_STANDALONE_ORIGIN` for an MCP served alone, to ID's origin and the registered URL's |
| `Invalid Toolbox configuration: TOOLBOX_ID_CLIENT_ID: …` at start | The Toolbox has no machine client to read who is calling | Start it with `bun mcp setup` and `bun mcp dev <mcp>`, which run it as `mcp-dev` |
| `The Toolbox cannot start: Database role answerable_mcps_toolbox may not serve MCPs: lacks USAGE on schema e2e…` | The MCP's schema is not made in your local `answerable_mcps` | `bun mcp dev <mcp>` migrates every MCP; or `bun mcp db e2e migrate`, for each MCP the message names |
| A tool call answers `UPSTREAM_UNAVAILABLE`, `Who you are could not be read…` | ID refused the Toolbox's machine client, or did not answer | Check `TOOLBOX_ID_CLIENT_ID`, `TOOLBOX_ID_CLIENT_SECRET` and the client's capability on ID's admin API; the Toolbox's log says what ID answered |
| `Tool <name> not found`, and `toolbox_whoami` lists no grants or too few | The Toolbox: no grant string covers the tool, its provider is not enabled for your organisation, or the token lacks `toolbox`. The e2e server: the token lacks the scope, for example `e2e:write` for `records_create` | Ask staff for an entitlement: `access_grant` in [the admin MCP](/docs/admin). The e2e server: once your organisation holds the scope, choose **Authenticate** again |
| A commit tool answers an error | The intent cannot be committed as it is | See [MCP errors](/docs/mcp/errors) |

Toolbox errors are in [The Toolbox](/docs/toolbox#errors) and [Administer the Toolbox](/docs/toolbox/admin#errors).
