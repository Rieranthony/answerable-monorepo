---
title: Test MCPs locally
description: "Sign organisations into the e2e MCP through real Answerable ID, a browser and the official MCP OAuth client."
---

```sh
bun install
(cd mcps/e2e && bun x playwright install chromium)
bun run mcp:test:e2e
```

Requires Bun 1.3.1 and Docker Compose. Run it from the repository root. It takes about ten seconds, exits non-zero on the first failure and removes its database and processes either way, including after Ctrl-C.

## What the acceptance proves

1. ID starts from production migrations, served through the restricted runtime role, and is provisioned only through its admin API: the MCP resource, a public client, three organisations with company sign-in, capabilities and entitlements.
2. The official MCP client follows the MCP's `401` to its metadata, discovers ID and builds the sign-in: PKCE S256, the MCP URL as `resource`, the advertised scopes plus `offline_access`.
3. A real browser completes ID's pages: email, company sign-in, organisation, consent. The callback carries ID's `iss` (RFC 9207), which the client checks.
4. The access token's audience is the MCP and its lifetime is the resource's 60 seconds.
5. For the fully entitled organisations, a 2025 client and a 2026-07-28 client both see all five tools, the prompt and the resource, and `identity_get` returns the selected organisation.
6. The partially entitled organisation receives a token without `e2e:write` and sees only `identity_get`, `records_list` and `records_show`. The consent page names what was not approved, writes fail and refresh keeps the subset.
7. Each organisation sees only its own records and cannot delete another's.
8. A second MCP at another URL refuses the token with `401`.
9. The client refreshes an expired access token by itself, and ID rotates the refresh token.
10. Disabling the organisation through the admin API makes refresh fail with `invalid_grant`; the issued access token keeps working until it expires.

The company directories are local test issuers. ID, its database role, its pages, token issuance, the MCP and the MCP client are real.

## Ports

| Service | Loopback port |
| --- | --- |
| Disposable PostgreSQL | `47532` |
| ID | `47600` |
| e2e MCP | `47602` |
| OAuth callback | `47603` |
| Second MCP | `47605` |

Keep these free. PostgreSQL belongs to the Compose project `answerable-mcp-e2e`; the run never reads your `DATABASE_URL`.

## Faster checks

```sh
bun run mcp:test
```

This runs the verifier, base and e2e suites with a local test issuer, including Chromium rendering the real MCP Apps view through the official host bridge. No Docker.

## Run the e2e MCP by hand

```sh
bun run --filter @answerable/mcp-e2e build
bun run mcp:dev
```

`mcp:dev` reads `MCP_ID_ISSUER`, `MCP_RESOURCE_URL` and `MCP_PORT` from the root `.env`. The resource and a client must already be registered in your local ID; [Connect Claude Code](/docs/mcp/claude-code) shows how.

## Limits

The acceptance does not certify an external host, a real company directory or a production deployment. [Connect Claude Code](/docs/mcp/claude-code) covers the first two by hand.
