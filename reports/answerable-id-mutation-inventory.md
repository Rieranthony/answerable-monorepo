# Administrative mutation inventory

This inventories the [registered route tables](../apps/id/src/http/admin/index.ts) and their declared contracts, as `apps/id/openapi.admin.json` publishes them. The [route contract test](../apps/id/src/http/admin/routes.test.ts) rejects missing replay headers and revision contracts; it does not substitute for runtime retry, failure or concurrency tests. Corrected on 20 October 2026 by the [v0 code audit](../docs/goals/v0-code-audit/report.md): `setClientOwner` went with the v0 schema audit (client ownership is immutable) and `revokeUserSession` with this audit (revoking every session of a user ends the one session as well).

**Totals:** 47 mutations. Each accepts an optional `Idempotency-Key`; a command without one is journalled under a server key, so it keeps its receipt and `Operation-Id` and a resend is a new command. Each answers with `Operation-Id` and `Idempotency-Replayed`. All seven PATCH operations accept optional If-Match. Group membership PUT and SSO PUT accept optional revision preconditions; omitted headers use the current row.

Tenant paths do not imply tenant write delegation. Groups, entitlements, domains, SSO configuration and organisation configuration require platform authority. The three member mutations are the tenant-write seam.

## Fresh human authority

Every route declares `x-fresh-authentication`. Of 47 mutations, 43 always require five-minute verified upstream freshness for humans. `updateOrganization` and `updateGroup` are display edits (a group patch has one field, its name). Resource patches are exempt only for `name`; client patches only for `name` and `uri`. Machines and root keep their own authority contracts. Authority is checked once, inside the command's transaction and before a replay; freshness is checked there and again after the command's body, so a window that ends during its waits rolls the command back.

## Transaction and evidence boundaries

All successful command effects, audit facts, durable subjects and receipts share the journal transaction. A command that changes nothing writes no audit event: its receipt, with outcome `noop`, is the record. Every audit event is version 1 with one payload per action ([docs/04](../docs/04-answerable-id-schema.md#audit-actions)).

| Family                       | Current local evidence                                                                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Client/resource              | Immutable identity/configuration, current-policy revocation, terminal deletion and exact local grant/token effects. Client owner sees counts/link; cross-tenant effects remain platform-only.    |
| Organisation/domain/provider | Current tenant routing/authentication revisions; tombstones, redacted credentials, exact tenant grant/child effects and cleared selections. Global users/sessions survive organisation deletion. |
| Member                       | Window/removal/reinstatement and observed before/after access; direct assignments soft-deleted, grants revoked, other tenants preserved. No automatic restoration.                               |
| Group/entitlement/capability | Exact UUID/principal/target/grant-kind, revisions/windows/scopes, broad audience sources where defined, terminal removals.                                                                       |
| User/session                 | Explicit global authority; exact local session/token/grant effects, repeated-disable reconciliation and retained history.                                                                        |

## Adoption rules

Retain route metadata tests plus meaningful HTTP, rollback, lost-response, concurrent duplicate, stale-write and process-death proofs. Inventory counts do not prove runtime behaviour. New routes adopt the same journal and explicit authority/freshness policy; no second framework is needed. Intended deployment fan-out and downstream revocation remain [external requirements](answerable-id-release-decision-plan.md#external-input-and-test-checklist).

Retries with the same key and canonical bound input return the permanent receipt at the original status; 204 remains empty. Fetch the current representation through the result reference. Response bodies are not stored; a lost client secret requires another rotation with a new key.
