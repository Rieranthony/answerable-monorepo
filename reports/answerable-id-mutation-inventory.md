# Administrative mutation inventory

This inventories the current [registered route tables](../apps/id/src/http/admin/index.ts), their declared API contracts and service implementations. All administrative mutation families use the existing journal wrappers. The [route contract test](../apps/id/src/http/admin/routes.test.ts) rejects missing replay headers and optional revision contracts; it does not substitute for runtime retry, failure or concurrency tests. The machine-readable [candidate inventory](id-release-contracts.json) is generated from current route tables.

**Current totals:** 49 mutations; all 49 declare required idempotency keys and operation/replay response headers; no replay contracts remain missing. All seven PATCH operations accept optional If-Match. Group membership window PUT and SSO PUT accept optional revision preconditions; omitted headers use the current row. The test asserts optional revision contracts; immutable owner verification and link creation are explicitly distinguished from configuration replacement.

Tenant paths do not imply tenant write delegation. In particular, groups, entitlements, domains, SSO configuration and organisation configuration currently require platform authority. Capability ceilings and trusted tenant contexts are implemented, but do not themselves delegate these routes. Broader tenant configuration remains outside the implemented public surface. The three member mutations remain the existing tenant-write seam.

## Fresh human authority

Every route declares `freshAuthentication`. Of 49 mutations, 45 always require five-minute verified upstream freshness for humans. `updateOrganization` is an ordinary display edit. Group/resource patches are exempt only for `name`; client patches only for `name`, `uri`, `contacts`. Machines and root retain their separate authority contracts. Replays and post-lock waits recheck current authority/freshness.

## Transaction and evidence boundaries

All successful command effects, audit facts, durable subjects and receipts share the existing journal transaction. All seven PATCH routes accept optional revision checks; SSO and group-assignment replacement PUTs also accept optional preconditions.

| Family                       | Current local evidence                                                                                                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Client/resource              | Immutable identity/configuration, current-policy revocation, terminal deletion and exact local grant/token effects. Client owner sees counts/link; cross-tenant effects remain platform-only.    |
| Organisation/domain/provider | Current tenant routing/authentication revisions; tombstones, redacted credentials, exact tenant grant/child effects and cleared selections. Global users/sessions survive organisation deletion. |
| Member                       | Window/removal/reinstatement and observed before/after access; direct assignments soft-deleted, grants revoked, other tenants preserved. No automatic restoration.                               |
| Group/entitlement/capability | Exact UUID/principal/target/grant-kind, revisions/windows/scopes, broad audience sources where defined, terminal removals.                                                                       |
| User/session                 | Explicit global authority; exact local session/token/grant effects, repeated-disable reconciliation and retained history.                                                                        |

Current user/organisation/group/client deletion events are version 3; smaller deletion and relationship payloads follow [T3's precise contract](id-soft-deletion.md). Production user outcomes are version 4 and machine issuance version 2. Interpret action and version together; retained old history is not a new writer contract.

## Adoption rules

Retain route metadata tests plus meaningful HTTP, rollback, lost-response, concurrent duplicate, stale-write, post-lock authority and process-death proofs. Inventory counts do not prove runtime behaviour. New routes must adopt the same journal and explicit authority/freshness policy; no second framework is needed.

The [acceptance report](id-release-acceptance.md) records final gates. Intended deployment fan-out and downstream revocation remain [external requirements](answerable-id-release-decision-plan.md#external-input-and-test-checklist). Local access observations do not isolate every concurrent causal change or prove remote logout.
